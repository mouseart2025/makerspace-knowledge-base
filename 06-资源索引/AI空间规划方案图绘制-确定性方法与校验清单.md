# AI空间规划方案图绘制：确定性方法与校验清单

> 核心结论：**从"理解平面图"到"画出区域划分/方案对比图"，全程必须用坐标驱动（矢量底图 + 真实坐标数据生成 SVG），绝不能靠 AI 视觉识别后凭记忆重绘。** 本文沉淀一套几何校验清单与实战错误案例库，供所有 AI 辅助空间规划项目复用，避免重复踩坑。
> 内化时间：2026-09 ｜ 验证场景：职业院校三专业共享创客空间（L型约434㎡，硬装已完成，楼上宿舍）
> 定位：本文是 [AI平面图理解与矢量提取方法论.md](AI平面图理解与矢量提取方法论.md) 的**下游篇**——底图提取完成后的"语义识别 → 区域划分 → 方案图绘制"三段进阶，每段都有"反复画错 → 沉淀为校验规则"的真实记录。

---

## 一、为什么方案图会"画乱"（三条失败路径）

本项目的方案图（区域划分图、两方案对比图）经历了多轮"离谱→修正"，复盘后归纳出三条必然失败的路径，以及唯一可靠路径：

| 路径 | 做法 | 失败原因 | 结论 |
|------|------|---------|------|
| ① 生成式图像模型重绘 | 用 Seedream/Midjourney 等"描述→画图" | AI 不理解平面图几何，L型是想象的，墙体/门窗/尺寸全幻觉 | ❌ 连底图都不该用 |
| ② AI 视觉看原图 + 目测重绘 | 让 AI 读图片、估坐标后手工画 SVG/HTML | 丢失凹凸转折；柱简化为统一方块；门位置靠猜；区域边界把"尺寸标注线"当成隔墙 | ⚠️ 细节必然丢失 |
| ③ 凭记忆/口头描述拼方案图 | 不查底图，直接画"大概布局" | 方向错、比例错、越界、缺构件 | ❌ 屡错屡犯 |
| **④ 坐标驱动生成** | **矢量底图提取坐标 → 真实坐标数据生成 SVG → 转PNG视觉验证** | —— | ✅ **唯一可靠路径** |

> 关键认知：**AI 擅长"理解意图+组织信息"，不擅长"精确画图"。** 方案图的几何部分要让 AI 做"数据搬运工"（把底图坐标原样搬进 SVG），而不是"画家"（凭印象重绘）。

## 二、三段进阶：语义识别 → 区域划分 → 方案图绘制

### 2.1 段1：语义识别（墙/柱/门/窗分类）——必须多轮人工校验

矢量底图提取后，要把路径分类成"墙体/柱子/门窗/设备"，这一步 AI 会犯大量语义错误，**必须人工逐类确认**。

本项目实测结论：

| 构件 | 常见错误 | 本项目最终确认 | 校验方法 |
|------|---------|--------------|---------|
| 墙体 | 把尺寸标注线/设备基座误判为墙体 | 墙6段 | 隔墙是**双线表示**（两条平行线夹墙厚），标注线是单线且带箭头 |
| 柱子 | 异形柱（T/L型）简化成方块；漏柱；把墙误判为柱 | 柱9根（含异形） | 柱子有填充色（黑/深色实心块），墙体是空心线 |
| 门 | **位置/数量/类型反复错**（本项目迭代9版） | 门5个（门1/3防火门、门2/4/5玻璃门） | 门=墙体开口+开向弧线；**门与门常成对南北正对**（门1↔门2、门3↔门4） |
| 窗 | 位置与柱重叠；漏数 | 窗21个 | 窗在墙体上的双线小段，不与柱重叠 |
| 设备基座 | **把图案误判为设备基座**（本项目2个"基座"经用户确认CAD无明示、现场无此物，属误识别，已剔除） | 0个 | 不能仅凭图案形状推断，需对照CAD原始标注与现场照片双确认 |

**门的语义识别口诀（本项目最大教训，迭代9版才正确）**：
```
门在墙体开口处 + 有开向弧线；
门类型看构造（防火门有门框/闭合器标识，玻璃门有双线玻璃标识）；
主入口方向看流量（本项目门5方向才是流量入口，门2看似居中但非入口）；
门的位置要结合"成对正对"关系交叉验证——门1↔门2南北正对、门3↔门4南北正对。
```

### 2.2 段2：区域划分（按自然柱墙分割）——注意边界口径

房间被隔墙/柱子自然划分成若干区域。**区域边界必须以自然柱墙为分割，且要精确落在墙柱之间，不能用近似线或尺寸标注线当边界。**

本项目6区域（A-F）划分的反复修正过程，抽象为三条规则：

| 规则 | 说明 | 本项目反例 |
|------|------|-----------|
| **隔墙是双线墙，不是标注线** | 真正的区域分界是墙（双线），红色尺寸标注线只是测量参考，不能当分界 | v1-v3 把 x=1308.8 / x=1963.3（标注线）当成分界，AB、BC 间距全错 |
| **柱作为边界要精确** | 相邻区共用柱子时，分界取"柱中/柱边"要统一口径；C区下边靠近柱8上边缘、F区上边靠近柱4下边缘 | v4 分界线离柱太远，v5 才贴合 |
| **柱是否计入区域要明确** | L型转角/密集柱区，柱体可能计入相邻区尺寸（如 E=9.90+0.50 含柱） | 区域尺寸标注 v6 时 D/E/F 把柱算错 |

**区域尺寸标注口径（本项目最终确认，可直接复用）**：
```
区域尺寸 = 墙体净距（含转角重叠区时明确归属）；
柱密集处：标"长×宽"时要注明是否含柱；
面积 = 长×宽，逐区核算后与甲方总面积对比（本项目6区合计424.8㎡ vs 甲方434㎡，差2.1%需标注）。
```

### 2.3 段3：方案图绘制（坐标驱动生成 SVG）——三条硬规则

方案图（功能分区落位、动线方案对比）必须：

1. **用真实坐标生成**：区域矩形、柱、门的坐标一律取自底图数据文件（如 elements.json），禁止手工估坐标。
2. **设置 viewBox 并检查越界**：所有元素（含箭头、文字）必须在 viewBox 范围内。**动线终点、箭头、文字标签是最容易越界的对象**，生成后逐一核对 x/y 范围。
3. **动线必须连续**：门→区域→辐射要一条连贯路径（折线或分段箭头首尾相连），不能出现"进入箭头止于 A、主线起点在 B"的断点。

## 三、几何校验清单（每次出图必查，可复用）

> 用法：每次生成区域划分图 / 方案对比图后，逐条过一遍，任何一条不通过即返工。

### A. 区域边界校验
- [ ] A1 区域边界是否以自然柱墙为界（非尺寸标注线、非近似线）？
- [ ] A2 边界是否精确落在墙柱之间（贴合柱边缘/柱中，而非留出空隙）？
- [ ] A3 相邻区域间隔处的柱子是否在图上？间隔宽度与柱/墙实际尺寸一致？
- [ ] A4 转角重叠区归属是否明确标注？
- [ ] A5 柱是否计入区域尺寸的口径是否一致（含柱/不含柱）？

### B. 构件校验
- [ ] B1 柱的数量/坐标与底图数据文件完全一致（**逐根核对，常见漏柱**）？
- [ ] B2 门的数量、位置、类型与已确认版本一致？成对正对关系正确？
- [ ] B3 窗不与其他构件重叠？
- [ ] B4 无"图案推断出的虚构构件"（如设备基座——需CAD+现场双确认）？

### C. 动线与越界校验
- [ ] C1 所有元素（矩形/箭头/文字/标注）都在 viewBox 范围内？**重点查横向/纵向动线终点、箭头多边形、旋转文字**？
- [ ] C2 动线是否连续（门→区域→辐射无断点）？
- [ ] C3 动线方向是否符合实际（进室内方向、人流走向）？**重点查"门在平面边缘时，进室内是向内侧还是外侧"**？
- [ ] C4 人流动线/物流动线/疏散动线是否区分或标注清楚？

### D. 视觉验证闭环（最重要）
- [ ] D1 生成 SVG 后是否**转成 PNG 用眼睛实际看**（`qlmanage -t -s 1200 -o <dir> <svg>` 后 Read 检查）？——**只看代码/坐标必然漏错，本项目所有"离谱"图都是没做视觉验证的版本**
- [ ] D2 检查是否有文字重叠、箭头穿墙、超出区域、方位标注方向是否正确？
- [ ] D3 尺寸/面积数字与 CAD 标注一致（可用 OCR 复核渲染结果，但小字 OCR 易误读，以源数据为准）？

## 四、实战错误案例库（本项目全记录）

> 每条都是真实踩过的坑，记录"错误现象 → 根因 → 防止方法"，后续项目直接对照，不必重犯。

### 案例1：门的识别迭代了9版才正确
- **现象**：门数量、位置、类型反复错；门2曾被画到西南角(846,1311)、门1画到门2对面等
- **根因**：凭视觉估算门位置；未结合"成对正对"关系；未区分防火门/玻璃门
- **防止**：用矢量提取的门弧线精确坐标 + 成对交叉验证 + 门类型标注（见2.1口诀）

### 案例2：把尺寸标注线当成区域分界（区域边界全错）
- **现象**：v1-v3 的 A/B/C 间隔位置全错，AB、BC 之间"250隔墙"没体现
- **根因**：AI 把红色尺寸标注线（x=1308.8/x=1963.3）的位置当成了隔墙位置
- **防止**：识别"双线墙 vs 单线标注线"，区域分界只认墙（见2.2规则）

### 案例3：区域尺寸标注算错（D/E/F 的 8.11m 是错的）
- **现象**：D/E/F 宽度被算成 8.11m（实际7.65m）；E 长 9.90 少算了含柱的0.50m
- **根因**：把相邻柱的间隔/柱宽错误并入区域宽度；E 区漏算柱子
- **防止**：区域尺寸=墙体净距，柱密集处明确含柱口径，逐区与 CAD 标注核对（见2.2）

### 案例4：方案图横向动线画出画面
- **现象**：横向辐射线终点 x=600，小于 viewBox 左边界760，整条线穿出画面
- **根因**：坐标用手估（想当然以为"到A区西端"即可），没核对 viewBox 范围
- **防止**：动线终点取区域边界真实坐标（如A区西边界 x=800），生成后过 C1 校验

### 案例5：方案2动线不连贯
- **现象**：门5进入箭头止于(1900,2345)，纵向主线起点在(1995,2070)，两线脱节
- **根因**：分段画动线时各段独立起止，未保证首尾相连
- **防止**：动线画成一条连续折线（门→上→汇入纵向→辐射），或明确连接节点（见2.3规则）

### 案例6：虚构构件（设备基座）
- **现象**：误识别出2个"设备基座"（X形图案），CAD 无明示、现场无此物
- **根因**：仅凭图案形状推断语义，未对照原始标注与现场照片
- **防止**：任何"推断出的构件"都要 CAD 原始标注 + 现场照片双确认（见2.1 B4 校验）

## 五、推荐工作流（可直接套用）

```
Step 1 矢量底图提取        → PyMuPDF 提取路径+颜色分类+clipPath裁剪（见《AI平面图理解与矢量提取方法论》）
Step 2 语义识别确认        → 墙/柱/门/窗分类，逐类与用户确认（门按成对关系交叉验证）
Step 3 保存坐标数据        → 输出 elements.json（含每个构件精确坐标），作为唯一坐标来源
Step 4 区域划分            → 按自然柱墙分割，边界精确落位，确认区域尺寸/面积口径
Step 5 方案图坐标生成      → 用坐标数据生成 SVG（区域/柱/门/动线全用真实坐标）
Step 6 几何校验清单        → 过第三章节 A/B/C 三类校验
Step 7 视觉验证            → 转PNG + 人工看图（过 D 校验），通过后再交付
```

**工具栈**：Python（PyMuPDF 提取 / Pillow 渲染）、SVG（viewBox + clipPath）、`qlmanage -t -s 1200 -o <dir> <svg>` 转 PNG 视觉验证。原始 DWG/DXF 可优先用 ezdxf 读取（信息更全）。
