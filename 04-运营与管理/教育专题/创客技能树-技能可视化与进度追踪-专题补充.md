## 二、★ 许可约束（本文最高价值段）

### 2.1 两份许可的对照

| 项 | 本库 | Maker Skill Trees |
|---|---|---|
| 许可 | **CC BY 4.0** | **CC BY-NC-SA 4.0** |
| 署名 | 要求 | 要求 |
| **商业使用** | **允许**（README 明示） | **禁止**（NC） |
| **相同方式共享** | 不要求 | **要求**（SA） |
| 是否可互相混合 | 可吸收更宽松者 | ⛔ **不可被 CC BY 4.0 作品吸收** |

### 2.2 为什么"署名即可用"的想法在这里不成立

NC 与 SA 是**两个都会传染的条款**，且传染方向是**向下**：

- 本库若纳入其素材 → 该素材（及据其改编的衍生内容）必须继续按 **NC-SA** 授权；
- 由于 SA 要求"衍生作品采用同一许可"，实际效果是**本库相关部分乃至整体被拖入 NC-SA**；
- 结果：**本库从"可商用"降级为"不可商用"**，与其信息卡、"给规划者 / 建设者 / 运营者三种用途"的定位直接冲突。

> ★ **这不是"能不能署名"的问题，是"许可方向不能倒流"的问题。** 署名义务可以履行，NC / SA 的传染无法通过署名解除。

### 2.3 ★ 新增一条许可纪律（建议写入 CONTRIBUTING 或 NOTICE）

本库 NOTICE 已确立：「第三方资料的授权状态不因本库采用 CC BY 4.0 而放宽」（以柴火《创客空间搭建及运营指南》CC BY-NC-SA 为例）。本文补上**反方向**的第三条：

| 方向 | 表述 |
|---|---|
| ①（已有） | 本库的宽松**不会**放宽第三方更严的授权 |
| ②（已有） | 第三方受版权保护的材料**只摘录要点、不整段转载** |
| ③（**本文新增**） | 引入含 **NC / SA** 条款的第三方材料，会**反向拉低本库自身的授权**——因此**评估一道关，不只是"能不能引用"，还有"引用了会不会把本库的授权改坏"** |

★ 操作判据一句话：**看许可里的 `NC` 与 `SA` 两个字母。有 NC → 不能进可商用库；有 SA → 会强迫本库改许可。只要出现任意一个，就只走"原理借鉴 + 外链指向"，不搬素材。**

## 四、它的组织原理（可借鉴的方法层）

| 要素 | 设计 | 为什么值得借鉴 |
|---|---|---|
| **载体** | 一页可打印图形，由**六边形瓦片**铺成 | 零设备门槛；可贴墙、可涂色、可拍照留存 |
| **难度轴** | 自下而上：底层是基础技能，顶层是需要综合能力的进阶目标 | ★ 与"能力矩阵"式表格相比，**空间位置本身就传达了进阶关系**，不需要额外解释 |
| **★ 记录方式** | 完成一格就涂色 | 极低操作成本；**不依赖任何系统**（这正是"做系统需商业许可"之外的一条自足路径） |
| **★ 设计哲学** | README 明示三点：瓦片是**建议**、可按自己的优先级与能力改；**不必完成到 100%**；可以**乱序**完成（但初学者从底层起） | ★ 这是它区别于"课程大纲 / 考核表"的关键——**它把完成度从"考核指标"改造成"自我对话"**，因此适配非正式学习场景，而不会制造达标压力 |
| **可重排** | 提供瓦片贴纸模板（可切割）覆盖原格 | 一张纸可复用、可按年重排——与"采购要写可移动性"的**同一种气质** |
| **数据形态** | `{ title, footer, row: {0…9: [每行 7 格]} }`——**三字段极简 schema** | 一个 YAML 三字段即可生成一张 SVG；**机器可读 + 人可读同时成立**，无私有格式锁定 |

## 六、★ 可以怎么用（不搬内容的前提下）

### 6.1 自制技能树（首选路径）

**条目源用本库自己的**[三专业典型实训项目库](三专业典型实训项目库.md)（智能制造 12 / AI 12 / 新能源汽车 10 个项目卡），按"底→顶"难度光谱排布，得到**本项目自己的三专业技能树**。

> ★ **骨架曾落盘、现已移出本库**（2026-09-22）：三专业 189 格的**具体展开**属**项目交付物**，已移至项目目录 「**委托项目的私有项目仓**」（含生成脚本与出图资产）。**本库只保留方法论** —— 而那次展开得出的**唯一一条本文未及的关键校正**仍留在本文：**危害等级轴必须与难度轴解耦**（实训场景里"学得早"与"碰得险"是两件事，照搬"越难越危险"会把 Class 4 高压作业排到底行）。★ 判据见 [CONTRIBUTING.md](../../CONTRIBUTING.md) §2.1「`scope` 怎么判？」。

这么做的三重好处：

1. **完全规避许可**——只借"网格 + 分层 + 可涂色"这个形态，不引用任何素材；
2. **口径更对**——实训项目卡已按"技能 / 设备 / 课时 / 考核 / 证书赛项"五维对齐，比国外通用技能树更贴本项目的 40 人班与三专业设置；
3. **单一数据源**——条目来自既有项目库，不需要维护第二套技能清单（符合本库"同一源驱动"纪律）。

### 6.2 与设备授权打通（派生用法）

把「危害四级 + 授权权限矩阵」映射为**点亮条件**：

| 技能树上的位置 | 对应的授权含义 |
|---|---|
| 底层若干格（基础安全、PPE、空间导览） | 可进入空间、可在监督下使用 Class 1 |
| 中层（按工艺分组的操作格） | 该工艺设备的独立操作资格（对应各设备等级） |
| 顶层（综合 / 排障 / 带人） | 可发证、可带新人（对应 Monitor 权限上限） |

★ **边界（必须写明）**：技能树是**可视化与激励工具，不是资格文件**。授权签署、培训留档、复审周期仍按既有安全制度执行——**墙上的格子不能替代签字**。

### 6.3 形态要点（自制时照抄这几条）

- 一页纸、格子化、可涂色；
- 难度自下而上，**位置即含义**；
- 明确写"可改、可乱序、不必 100% 完成"——**否则它就退化成考核表**；
- 附一张空白模板 + 一排可替换贴纸（对应"可重排"）。

## 八、不纳入清单与理由

| 不纳入 | 理由 |
|---|---|
| **任何 SVG / PDF / PNG / AI / PPTX 素材**（含模板与贴纸） | CC BY-NC-SA 4.0 的 **NC + SA 双条款**，纳入会把本库整体授权拖入 NC-SA（§二） |
| **YAML / JSON 中的技能条目文本**（含 `_zh.yml` 中文版） | 条目文本属**表达**而非事实；**中文翻译同受 NC-SA 约束**，不因语言豁免 |
| **以其为数据源构建软件 / App / 系统** | README 明确需**商业许可**（通过赞助解锁）；这与本库"可自由复用"的定位不符 |
| **把它当"课程大纲 / 考核表"使用** | 设计意图是**可选目标集合**（明示"瓦片是建议""不必 100% 完成""可乱序"）；当大纲用属**误用**，会制造它刻意避免的达标压力 |
| **把其工具链一并引入** | 三项配套工具星标 3 / 7 / 11、活跃度低；本项目"上墙"需求用自制即可满足，引入属过度装配 |
| **在本文中摘录其条目举例** | 即便"举例 1–2 条"在合理引用范围内，**也因此丧失可复制性而无实际收益**——只描述结构即可 |

## 九、落地建议

1. **P0 · 记一条许可纪律** —— 把 §2.3 的第三条写入 [CONTRIBUTING](../../CONTRIBUTING.md) §三 或 `NOTICE`：**引入含 NC / SA 条款的第三方材料会反向拉低本库授权**；并给出操作判据"看见 `NC` 或 `SA` 就只走原理借鉴 + 外链"。
   **不要做什么**：不要因为"有中文版、声明允许在创客空间使用"就放宽——**"允许你把打印件用在创客空间"≠"允许你把素材放进另一个开源库"**，这是两个不同层级的授权。
2. **P1 · 自制三专业技能树** —— 条目源 = [三专业典型实训项目库](三专业典型实训项目库.md)；形态要点照 §6.3。
   **不要做什么**：不要搬运它的入门条目做"起步模板"——**一旦搬了，整棵树就落进 NC-SA**。
3. **P1 · 与设备授权打通** —— 把危害四级 + 授权权限矩阵映射为点亮条件（§6.2）。
   **不要做什么**：不要让技能树取代授权签署与培训留档；墙上的格子只是可视化。
4. **P2 · 与 Fab I Can 分工** —— Fab I Can 定条目、技能树做学员侧可视化。
   **不要做什么**：不要同时维护两套条目清单。
5. **P2 · 生态只观察不引入** —— 若日后确需"批量生成"，`Generator`（MIT）与 `skilltreetool`（Apache-2.0）许可宽松可移植，届时再评估。
   **不要做什么**：不要为"看齐完整性"而引入三个低活跃度工具。
