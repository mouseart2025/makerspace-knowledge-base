# 创客空间作品权属与知识产权管理

> **本文是什么**：一份面向创客空间/实训室的**作品权属判定与知识产权操作规范**——回答"学生做的东西归谁""教师指导的作品算不算职务作品""企业出题、学生作答的成果怎么分""用了开源库/开源硬件能不能商用""AI 参与生成的作品有没有版权"这些高频且高风险的问题。
> **为什么需要**：创客空间的产出天然是**多方参与、边界模糊**的——设备是学校的、材料可能是企业赞助的、想法有教师指导、代码抄了开源项目、学生的灵感来自课堂。**在没有事先约定的情况下，一旦作品产生商业价值或引发争议，任何一方都很难证明自己"该拿多少"。** 本库此前在《中国创客空间案例》中已记录"开源与知识产权的平衡机制缺失（分享后被复制的回报纠纷）"这一真实痛点，本文是对它的正面回应。
> **口径说明（重要）**：本文的法规**名称**与**一般原则**来自公开法律；但**具体法条序号、司法裁判的最新口径、地方科技成果转化政策、以及合同条款的适用性**，在落地前**必须由本单位法务或专业律师人工复核**。本文不构成法律意见，涉及真实权益分配时请以书面合同与专业意见为准。
> **脱敏声明**：本文组织一律写为"某职业院校""某科普场馆""某企业合作方"，不含任何真实委托方名称、真实人员信息或本地路径。

## 一、为什么创客空间是知识产权的高风险区

普通课堂的产出多为标准化作业，权属争议少；创客空间的产出**天然是"创作物"**——可申请外观设计、可申软著、可申专利、可开源、可商用。它的高风险来自五个结构性特征：

| 特征 | 说明 | 引发的典型争议 |
|------|------|--------------|
| **多方参与** | 学生、教师、企业导师、外部志愿者共同完成 | 谁是"创作者"？谁有权处置？ |
| **资源混合** | 学校场地设备 + 企业材料/资金 + 开源代码/设计 | 学校/企业能否主张权利？开源许可是否被违反？ |
| **正式与非正式并存** | 课程项目、竞赛作品、个人兴趣项目混在一起 | 哪些算"职务/教学成果"，哪些算个人创作？ |
| **价值不确定性** | 项目初期没人知道它值不值钱 | 事后发现值钱时，早期"没约定"就成了争议源 |
| **开源文化冲突** | 创客文化鼓励分享，但机构有保密与商业化诉求 | 分享了还能不能申专利？企业素材能不能发上网？ |

> ★ **核心结论**：**权属问题不能等到"值钱了再谈"。** 事前一份写清归属的协议，成本是几百字；事后一场权属争议，成本可能是整个项目停滞、甚至双方对簿公堂。**本文的全部价值，就是把"谈不拢"变成"有默认规则可依"。**

## 二、先分清四类权利，别混成一个"知识产权"

日常说"这是我的知识产权"，在专业上其实是**四类彼此独立的权利**。混用会导致约定无效或保护错位。

| 权利类型 | 保护对象 | 取得方式 | 保护期限（一般情形） | 创客空间常见载体 |
|---------|---------|---------|-------------------|----------------|
| **著作权（版权）** | 文学、艺术、科学作品的表达形式 | **创作完成即自动产生**，无需登记（登记为初步证据） | 自然人作品：作者终生 + 死后 50 年；法人作品/职务作品按类型区分 | 设计图、代码、说明书、教学课件、摄影/视频、3D 模型文件 |
| **专利权** | 发明、实用新型、外观设计的技术方案/设计 | **须申请授权**，先申请原则 | 发明 20 年；实用新型 10 年；外观设计 15 年（自申请日起算，均需依法维持） | 装置结构、机构方案、外观造型 |
| **商标权** | 区分商品/服务来源的标志 | **须申请注册** | 10 年，可续展 | 空间名称、课程品牌、活动 IP |
| **商业秘密** | 不为公众所知悉、有商业价值、采取保密措施的信息 | **自动产生**（以保密措施为前提） | 无固定期限，一旦公开即丧失 | 工艺参数、客户名单、未公开的配方/算法 |

**四条实用分辨**：

1. **"我画的图"→ 著作权**；"我画的图和别人做的东西都像"→ 可能涉及外观设计专利或侵权。
2. **"我写了个算法"→ 代码本身是著作权，方法本身可能可申专利**（软件方法专利）。
3. **"我公开了就没保护了"不完全对**：著作权公开不影响；专利**公开会破坏新颖性**（申请前公开=大概率无法授权）；商业秘密**公开即灭失**。
4. **登记不是取得权利的前提，但是重要证据**：著作权登记、软著登记、专利申请都能在争议中大幅降低举证难度。

## 三、权属判定：一张决策表说清"归谁"

### 3.1 主判定表

| 场景 | 默认权属（无特别约定时） | 关键变量 | 是否需要书面约定 |
|------|----------------------|---------|----------------|
| **学生独立完成、与课程任务无关** | 学生个人 | 是否使用了学校**实质性资源** | 一般不需要，但建议登记 |
| **学生完成课程作业/实训任务** | 通常归学生；若属校方组织的职务性创作，可能归学校（依约定与规章） | 学校规章制度有无明确约定、是否属"为完成法人任务" | **建议约定**（尤其可商业化项目） |
| **教师指导、学生主导完成** | 学生为作者；教师贡献若构成"创作性表达"可成为合作作者 | 教师的贡献是"指导"还是"共同创作" | **强烈建议约定** |
| **教师为完成本职工作创作（课件、教材、软件）** | 一般构成**职务作品**：作者享有署名权，单位在业务范围内优先使用；特定情形（如主要利用单位物质技术条件且单位担责）单位可享有著作权 | 是否利用单位物质技术条件、是否由单位承担责任 | **必须依单位规章** |
| **校企合作项目成果** | **完全取决于合同约定**；无约定时按贡献与作品类型分别判断 | 合同条款、经费来源、是否属委托开发 | **必须有书面合同** |
| **企业出题、学生解题（非委托开发）** | 学生作品归学生；企业获得使用权需另行约定 | 是否支付对价、是否属"委托" | **必须有书面约定** |
| **企业委托学校/空间开发** | 依《著作权法》委托作品规则：**无约定时著作权归受托人（创作方）**，委托人在约定使用范围内可用 | 合同是否明确约定归属 | **必须书面明确** |
| **竞赛作品** | 依竞赛规则与参赛协议；一般归参赛者，主办方取得展示/宣传许可 | 竞赛规则中对作品权的约定 | 参赛前读规则并留存 |
| **多方共同创作** | **合作作品**：著作权由合作作者共同享有；不可分割使用的需协商一致 | 各方贡献是否可分割 | **必须有书面约定** |
| **使用开源代码/硬件设计改造** | 新作品可能有著作权，但**衍生作品须遵守原开源许可** | 原许可类型（MIT/GPL/CC 等） | 保留许可与署名文件 |
| **AI 参与生成** | 现行法律下**AI 通常不构成"作者"**；人类有独创性贡献的部分可受保护，纯 AI 输出保护存在不确定性 | 人类参与程度、工具条款、训练数据来源 | **建议披露与约定** |

> ⚠️ **最重要的一条**：上表的"默认"**只有"没有约定时"才适用**。**校企合作、委托开发、可商业化项目，只要有一方要主张权利，就必须事先写清**——事后的"默认规则"往往是双方都不满意的结果。

### 3.2 三个高频误判

| 误判 | 事实 | 后果 |
|------|------|------|
| "学生用了学校的设备，所以作品归学校" | **使用设备≠取得著作权**；著作权归创作者，除非有明确约定或构成职务作品 | 学校主张无效，或教师/学生权益受损 |
| "企业出钱出材料，成果自然归企业" | 无约定的委托开发，**著作权默认归受托人** | 企业出资却无法独占成果 |
| "参加比赛的作品归主办方" | 多数竞赛规则只要求**展示与非独占宣传许可**，不转移著作权 | 参赛者误让权利，或主办方越界使用 |

## 四、四类常见创客作品的具体判定

### 4.1 学生创客作品

| 情形 | 判定要点 | 建议做法 |
|------|---------|---------|
| 课程内完成 | 看学校规章有无职务性约定；看教师是否为共同创作者 | 项目立项时签**一页纸权属备忘**：归属 + 学校使用权 + 商业化时的分成原则 |
| 竞赛作品 | 看竞赛规则；团队内部也需约定 | 团队内部先签**贡献清单与权属约定**（谁贡献了什么、署名顺序、后续处置权） |
| 个人兴趣项目 | 归学生个人 | 若使用空间资源（材料/设备/机时），可约定"资源使用对价"而非直接主张著作权 |
| 毕业设计/课题 | 可能涉及导师课题组既有成果 | 明确**背景知识产权**与**新产生成果**分别归属 |

### 4.2 教师开发的教学资源

| 资源类型 | 常见权属安排 | 注意 |
|---------|-------------|------|
| 课件、教案 | 视单位规章，多为职务作品 | 单位业务范围内优先使用；作者保留署名与部分权利 |
| 教材/专著 | 常由出版合同另行约定 | 出版社合同中的授权范围要看清（是否含电子版、改编权） |
| 软件/教学平台 | 可能构成职务作品或委托开发 | 若申请软著，申请人写谁需与单位确认 |
| 教具/装置设计 | 可申外观/实用新型 | 申请前确认不侵犯他人在先权利 |

### 4.3 校企合作成果

这是**争议最集中、最需要合同**的一类。合同至少应写明：

| 条款 | 必须明确的内容 |
|------|--------------|
| **背景知识产权** | 各方在合作前已有的技术/素材，**不因合作而转移**，仅授予项目所需的使用许可 |
| **新产生成果归属** | 逐项写明：归校方 / 归企业 / 共有（共有须写清行使规则与收益分配） |
| **委托开发约定** | 若为委托开发，**明确著作权归属**（否则默认归受托人） |
| **学生权益** | 学生作者的署名权（不可转让）与收益分享安排 |
| **使用许可** | 未取得所有权的一方，取得何种范围（时间/地域/用途）的许可 |
| **保密义务** | 哪些信息属商业秘密、保密期限、违反责任 |
| **发表与宣传** | 论文/公众号/比赛披露前是否需企业同意，审批时限 |
| **成果转化与收益** | 转化方式、收益分配比例、决策程序 |
| **退出与终止** | 合作终止后成果如何处置、材料如何返还 |

### 4.4 开源作品与衍生

| 许可类型 | 典型代表 | 关键义务 | 对创客项目的含义 |
|---------|---------|---------|----------------|
| **宽松型** | MIT、Apache 2.0、BSD | 保留版权声明与许可文本；Apache 还需注明修改 | 可商用、可闭源，**最省心** |
| **传染型（强）** | GPL 系列 | 衍生作品**也须以 GPL 发布并提供源码** | 若你的项目要闭源商用，**不能混入 GPL 代码** |
| **传染型（弱）** | LGPL | 库本身修改部分需开放，链接使用可放宽 | 用动态链接方式使用需谨慎 |
| **内容型** | CC BY / CC BY-SA / CC BY-NC / CC BY-ND | 署名 / 相同方式共享 / **禁止商用** / **禁止改编** | **NC 与 ND 是创客项目最容易踩的坑** |
| **公共领域** | CC0、公有领域 | 无义务 | 可自由使用 |

**开源合规四条纪律**：

1. **建立"依赖清单"**：项目用了哪些开源库/开源硬件设计，各自什么许可，**落地前逐条核对**；
2. **区分"使用"与"衍生"**：调用一个库 vs 修改并分发它，义务完全不同；
3. **保留署名与许可文本**：宽松许可不是"随便用"，**保留声明是硬性要求**；
4. **NC/ND 要特别标注**：教学使用（非商用）通常可以，**一旦对外收费或商业化就触发限制**——这与创客空间"对外服务变现"直接冲突，必须在选材阶段规避。

## 五、AI 生成内容：一个尚未定论但必须管理的问题

AI 已经深度进入创客流程（生图、生码、生文、生 3D 模型），由此产生三类新问题：

| 问题 | 现状（口径需人工复核） | 建议做法 |
|------|--------------------|---------|
| **AI 输出有没有著作权** | 通说认为**AI 本身不是作者**；人类有独创性智力投入的部分可能受保护，纯 AI 输出的可保护性存在不确定性 | 教学与对外发布时**不把纯 AI 输出当"原创作品"主张**；重要作品保留人类创作过程的证据 |
| **训练数据与输出侵权** | 输出可能与训练数据中的作品实质性相似 | 商用前做**相似性核查**；避免以"模仿某在世艺术家风格"作为明确指令 |
| **上传内容的数据风险** | 上传内容可能被服务方留存或用于训练 | 与 [数据合规与个人信息保护.md](数据合规与个人信息保护.md) 的 AI 白名单联动；**禁止上传**他人未公开作品、含个人信息的数据 |

**AI 使用披露的最小模板（项目交付时附）**：

| 项 | 内容 |
|----|------|
| 使用了哪些 AI 工具 | ____（工具名 + 版本/日期） |
| AI 参与了哪些环节 | □ 头脑风暴 □ 文案 □ 图像 □ 代码 □ 3D 模型 □ 其他____ |
| 人类贡献 | ____（如：概念设定、结构设计、关键修改、最终审定） |
| 是否上传第三方内容 | □ 否 □ 是（说明授权来源） |
| 商业化前核查 | □ 已做相似性核查 □ 不涉及商用 |

> ★ **给教学的建议**：把"AI 使用披露"变成学生的**常规交付项**，而不是事后追查项。这既是合规，也是 AI 素养教育的一部分。

## 六、成果保护：什么时候申请什么

| 成果形态 | 推荐保护方式 | 时机 | 备注 |
|---------|-------------|------|------|
| 设计图、课件、视频、模型文件 | **著作权登记** | 创作完成后即可 | 成本低、周期短，是**性价比最高的第一步** |
| 软件 | **计算机软件著作权登记** | 开发完成后 | 登记材料含源码与说明文档，需提前整理 |
| 有结构/机构创新 | **实用新型专利** | **公开/销售前**申请 | 授权较快；注意先申请后公开 |
| 新方法/新工艺/新材料 | **发明专利** | 公开前申请 | 周期长；评估商业价值后再投入 |
| 造型/外观 | **外观设计专利** | 公开前申请 | 与著作权可并行 |
| 品牌/课程名 | **商标注册** | 投入使用前后均可 | 注意先检索是否被抢注 |
| 工艺参数、客户信息 | **商业秘密管理** | 形成时即采取保密措施 | 访问控制 + 保密协议 + 标识 |
| 不适合独占的内容 | **主动开源**（选合适许可） | 发布时附许可 | 见 §七 |

**申请前三问**：

1. **是否已公开**？——专利申请前公开会破坏新颖性（多数情形）；
2. **是否侵犯他人在先权利**？——先做检索；
3. **是否真的需要独占**？——教学类成果有时开源的价值大于独占。

## 七、主动开源：不是"放弃权利"，而是"选择策略"

创客文化以分享为底色，但"开源"需要**有意识地选许可**，而不是"发到网上就是开源"。

| 目的 | 推荐许可 | 说明 |
|------|---------|------|
| 让尽量多人自由使用（含商用） | MIT / Apache 2.0（代码）、CC BY 4.0（内容） | 本知识库自身采用 **CC BY 4.0** |
| 要求衍生作品同样开源 | GPL 系列 / CC BY-SA | 适合社区共建项目 |
| 允许使用但不允许商用 | CC BY-NC | **注意：与对外服务变现冲突，教育项目慎选** |
| 允许传播但不允许修改 | CC BY-ND | 适合成果展示，不适合协作开发 |
| 完全放弃权利 | CC0 | 适合工具、模板类 |

**开源的三个前置检查**：

1. **是否有权开源**——若成果含企业素材、委托开发内容或职务作品，需先取得权利人或单位同意；
2. **是否含他人权利**——第三方图片、字体、音乐、数据集、开源代码，各自许可是否允许再分发；
3. **是否泄露敏感信息**——个人隐私、商业秘密、未公开的项目信息（与数据合规联动）。

> ⚠️ **反面案例（本库已记录）**：分享后被他人复制用于商业用途，因事先没有许可约定，造成"回报纠纷"。**开源不等于无商业安排**——想清楚"开源什么、保留什么、商用怎么合作"，比事后追责更有效。

## 九、知识产权台账：把权利"管起来"

权属制度如果不落到**台账**，一年后没人说得清"哪些成果、什么状态、谁负责"。

| 字段 | 说明 |
|------|------|
| 成果编号 | 唯一编号（建议 `IP-年份-序号`） |
| 成果名称 | 与作品一致 |
| 类型 | 著作权/软著/专利/商标/商业秘密/开源 |
| 创作者与权属方 | 个人/团队/学校/企业/共有 |
| 状态 | 未申请/申请中/已授权/已登记/已开源/已放弃 |
| 关键日期 | 创作完成日、申请日、公开日、到期日 |
| 相关合同 | 关联的权属备忘/合作协议编号 |
| 责任人 | 谁负责维护与续费（专利年费、商标续展） |
| 复核周期 | 建议每年复核一次状态与到期提醒 |

## 十一、常见坑

| # | 坑 | 后果 | 纠正 |
|---|----|------|------|
| 1 | 认为"用了学校设备作品就归学校" | 主张无效 | 以约定为准，不以资源使用为准 |
| 2 | 校企合作只在口头上说"成果共享" | 权利不清、无法执行 | 写清共有行使规则与收益分配 |
| 3 | 先发公众号再申专利 | 丧失新颖性 | 申请优先，公开随后 |
| 4 | 混入 GPL 代码后项目要闭源商用 | 违约风险 | 立项时做依赖许可清单 |
| 5 | 用 CC BY-NC 素材做收费课程 | 违反许可 | 选材阶段规避 NC/ND |
| 6 | 把 AI 生成图当"原创作品"申明权利 | 保护基础不稳 | 保留人类创作过程证据 + 披露 |
| 7 | 学生作品被反复用于招生宣传而无授权 | 侵权 + 伤害信任 | 使用授权 + 可撤回机制 |
| 8 | 只登记不管理，专利年费断缴 | 权利失效 | 台账 + 到期提醒 |
