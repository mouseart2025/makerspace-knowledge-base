# 知识库更新日志

> **本文件是什么**：本库全部新增 / 修订 / 治理动作的**登记台账**（倒序，最新在上），是「哪一版为准」的辅助证据链，也是 [知识库覆盖度分析与补充路线图](知识库覆盖度分析与补充路线图.md) 的配套执行记录。
> **本文件不是什么**：**不是**论证存档，也**不是**文档正文的替代品 —— 每条只登记「改了什么 + 判定要点 + 详情去哪看」。
>
> **★ 日志写法纪律（2026-09-22 立）**
>
> 1. **单条内容建议 ≤ 900 字符**。论证过程、推导步骤、完整枚举**一律留在对应文档里**，本表只留结论与可核查数值。
> 2. **可核查数值必须写全**（星标 / 许可 / 日期 / 条号 / 字数），不得用「大幅提升」这类模糊表述。
> 3. **提交哈希不入档**：本仓库曾做过一次历史脱敏重写（`git filter-repo`），旧提交哈希全部失效；日志统一用「日期 + 变更内容」定位，不写哈希。
> 4. **本表在 2026-09-22 做过一次「登记式重写」**：此前 §6.1 的逐字详版（33,288 字符 / 51 条，单日最高 15,195 字符）已按上述纪律压缩，**无内容删失** —— 论证在各自文档中完整存在；重写前原文可从本次重写之前的历史提交取回。
> 5. **★ 跨月即切分卷**（2026-09-22 立）：本文件只保留**当月**条目；进入新月份时，把上月整月条目切出为 `知识库更新日志-YYYY-MM.md`，并在下方「已归档月份」补链接。**月份边界即切点，无需人工判断何时该拆**。
> 6. 新增文档请同时完成**三处登记**（[README](../README.md) 结构树 / [GLOSSARY 检索索引](../06-资源索引/GLOSSARY检索索引.md) / 本表），并保证**至少一个 md 入链**，否则自检会报「孤岛」。
