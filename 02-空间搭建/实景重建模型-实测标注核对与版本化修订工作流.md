# 实景重建模型的实测核对与版本化修订工作流

> 配套文档：初版怎么从扫描/实测产物重建可编辑模型，见 [实景三维重建-AI驱动Blender原生建模工作流.md](实景三维重建-AI驱动Blender原生建模工作流.md)；模型做好后怎么发布到网页/飞书，见 [三维模型网页发布与飞书归档-model-viewer工作流.md](../06-资源索引/三维模型网页发布与飞书归档-model-viewer工作流.md)。
>
> 本文解决的是**初版模型交付之后**的问题：用户拿着实测模型逐项核对，指出"少了一面墙""很多标注细节没实现"。如何把这类反馈做成一套**可复算、可追溯、不破坏旧版本**的修订闭环，而不是边看边改、改完无法自证。

---

## 〇、适用场景与一句话方法

适用于：已有一份"结构优先"的重建模型（Blender 原生分件），同时保留着**带尺寸标注的实测源模型**（SketchUp/Revit 等可通过 API 读取的格式）。

一句话方法：**把"看着像不像"升级为"逐条标注 + 逐片面片的双证据对账"**——

1. 从实测源模型提取**每一条尺寸标注的两个端点坐标**（不是只提取标注文字）；
2. 对实测模型的**全部面片做几何聚类**（常数 X / 常数 Y 面 → 墙线、柱脚印、窗洞边界）；
3. 两类证据互相印证后，改写结构化几何 JSON，从零重建新版本；
4. 三进程验收 + 对照图 + 修订说明，旧版本文件全部保留。

实战锚点（某 L 型已建空间，约 32.5m×33.6m、六个分区）：68 条线性标注、415 个面片，模型经 v1（初版 320 对象）→ v2（补 1 面漏墙，321 对象）→ v3（全量标注落实，357 对象）三轮，每轮均从零重建并通过 14 项自动断言。

## 一、为什么"只提取标注文字"不够

初版重建时常见做法是遍历标注实体，只读出文本（"960mm""725mm"）和标注中心点。这会留下两个致命缺口：

| 缺口 | 后果 |
|---|---|
| 只有尺寸数值，没有**标注的是哪两个特征**（哪两个面、哪两个柱中） | 数值对不上模型时无法定位，只能靠人眼猜 |
| 只有中心点，没有**起终点** | 无法判断标注沿哪根轴、量到的是结构面还是完成面 |

**结论：标注实体必须提取起点/终点坐标。** 标注端点 + 标注文本，等于把实测人员在模型里画下的每一条尺寸线变成了机器可对账的"约束方程"。

### 1.1 SketchUp Ruby API 提取标注端点的坑（DimensionLinear）

通过 SketchUp MCP（本地 Ruby 控制台桥）执行：

```ruby
model = Sketchup.active_model
model.active_entities.grep(Sketchup::DimensionLinear).each do |d|
  # 坑：DimensionLinear 没有 start_point / end_point 方法
  s, e = d.start, d.end          # 返回值类型不固定！
  # s/e 可能是：
  #   (a) Sketchup::Vertex          → 用 s.position
  #   (b) Array[Vertex, Point3d]    → 必须取出其中的 Point3d
  #   (c) Geom::Point3d             → 直接用
  def to_pt(x)
    return x.position if x.is_a?(Sketchup::Vertex)
    if x.is_a?(Array)
      p = x.find { |i| i.is_a?(Geom::Point3d) }
      return p if p
      return x.first.position if x.first.is_a?(Sketchup::Vertex)
    end
    x
  end
  puts [d.display_text, to_pt(s).to_a, to_pt(e).to_a].inspect
end
```

直接 `Geom::Point3d.new(array)` 会报 `can't convert Vertex into Float`——这是最容易卡住的地方。

### 1.2 双坐标系：一份纯平移换算表

实测模型坐标与重建模型坐标通常只差一个平移（导入参考件时挪过原点）。在项目里固定一张换算表并写进 JSON 元数据，例如：

```
x_设计 = x_实测 + 32475 ;  y_设计 = y_实测 + 33700 ;  z 不变
```

所有提取结果落盘前统一换算；换算常数本身作为数据源字段接受验收，避免每个脚本各加各的偏移。

## 二、第二证据：面片聚类还原"实测到底建了什么"

标注会漏标、错标，且只覆盖关键尺寸；**面片（Face）是实测模型几何的完整留痕**。把全部面片导出（位置、包围盒、法向、面积）后离线聚类：

### 2.1 竖直面片 → 墙线与柱位

- 法向沿 X 轴（常数 X 面）的面片按 **x 值聚类**：成对出现的两个 x（内皮/外皮）就是一段墙，簇的 y 范围给出墙段起止；
- 法向沿 Y 轴同理；
- 墙厚 = 成对 x 之差（实战中发现东墙不是想当然的 200，而是 **420**，窗位还内凹 80）；
- 墙之间的短常数面簇 = 柱/壁柱的侧面：按 x/y 范围合并出柱脚印。**以竖直面为准**，不要只靠水平面聚类柱帽——柱顶常与墙顶/板顶共面合并，水平面簇会"消失"，但柱脚的竖直面一定在。

### 2.2 窗洞与凹龛

- 墙上同高度成对的小常数面（jambs）+ 窗台/窗顶水平面 → 逐扇窗的洞口边界，直接得到每扇窗的**宽度、中心、窗台高、窗顶高**；
- 墙内侧一整条通长、在窗位留洞的厚 230 左右的面片带 = 包管/暖气罩完成面（初版完全没建的构件，正是靠"这些面片归不进任何已知墙"暴露出来的）。

### 2.3 聚类的工程要点

- 容差按建模精度取（实测模型 1mm 级，聚类容差 5–10mm，完成面进退另算）；
- 共面合并会让柱帽、墙顶、板顶合成一个大面，**缺失某个 h 面簇不等于构件不存在**，必须用 v 面反证；
- 每个结论都要能写出"证据三元组"：**标注编号/尺寸 + 面片包围盒 + 渲染目视**，三者至少占二才允许改模型。

## 三、差异分级与处置原则

对账后差异按四类处理，修订说明里逐类登记：

| 级别 | 类型 | 处置 | 例子 |
|---|---|---|---|
| D1 | 坐标/尺寸偏差 | 以面片+标注双证据为准全模型联动修改 | 墙中心线整体偏 50mm；柱位偏 50–350mm；双柱中距 1100 实为 700 |
| D2 | 构件缺失 | 新建独立分件入对应集合 | 漏画的隔墙；墙内侧包管凹龛带（40 个分件） |
| D3 | 初版推断构件实测不存在 | **删除**，并在修订说明中留痕 | 初版按对称习惯加的 5 根壁柱，面片里无任何痕迹 |
| D4 | 构造取值无实测 | 保留常规取值，写入 known_gaps | 门框 80、窗框 40、门扇 45 厚 |

两条纪律：

1. **"待现场复核"只能给真正无法从现有证据判定的项**（如一个 213mm 的墙端断口是预留还是未砌完）；能从面片判定的不许悬置。
2. **改变面积/分区边界的修订必须重算下游数据**（分区净面积、设备可用净宽），并在说明中同时给出新旧值与口径（中心线口径 vs 内墙内皮净尺寸口径不可混用）。

## 四、非破坏版本化流水线（vN 约定）

### 4.1 单一数据源 + 版本并行

```
research/asbuilt_geometry.json        # v1 数据源，冻结不动
research/asbuilt_geometry_v2.json     # v2 = v1 全文 + changes_v2 + known_gaps_v2
research/asbuilt_geometry_v3.json     # v3 = v2 全文 + changes_v3 + known_gaps_v3
output/reconstruction_native_vN.blend # 每版成品并行保留
output/view_*_vN.png                  # 每版渲染图带版本后缀
模型修订说明-vN.md                     # 只记 v(N-1)→vN 增量
```

- 建模脚本读 JSON 从零生成，**绝不在旧 blend 上手工改了再另存**——否则脚本与成品会脱节；
- JSON 内显式写 `changes_vN`（数组，每条：部位/旧值/新值/证据）与 `known_gaps_vN`（数组，每条：现象/当前表达/待核动作）；
- 脚本把版本号、数据源、版本说明写进 blend 场景自定义属性，打开成品即可溯源。

### 4.2 三进程验收（防"脚本里对、文件里错"）

无头模式下分三个独立 Blender 进程执行，任何一步失败即阻断交付：

| 进程 | 动作 | 验收内容 |
|---|---|---|
| 1 build | `blender --background --python build_native.py -- out_vN.blend geo_vN.json` | 从零重建成功；对象总数 = 期望值 |
| 2 edit | 第二个进程打开**成品 blend**，做真实编辑（开门 30°、移柱、整组窗平移）后另存 | 验证成品可编辑、父子关系/约束正确（parent 前必须 `view_layer.update()`） |
| 3 assert | 第三个进程重开编辑后文件 | 断言编辑已持久化、构件数量/关键坐标/材质集合/旧误建构件未复活，输出 ALL_PASS |

断言要参数化到版本（期望值随 vN 分支取），并包含**负向断言**（"被删除的 5 根壁柱不存在"），防止旧构件在重建中复活。

### 4.3 对照图与修订说明

- **俯视新旧并列图**：同机位渲染 v(N-1) 与 vN，红圈编号标注每处修订，图上编号与修订说明表格一一对应；
- **专项对照图**：新增构件做"实测截图 ↔ 新模型同视角"三联（实测轴测、模型正视、近景）；
- 修订说明固定章节：结论 → 核对方法 → 分类修订表（旧值/新值/证据）→ 验收记录（三进程原文）→ known_gaps → 文件清单。

### 4.4 ★ 复核要能「在旧口径复现原问题」（2026-09 增补）

**症状**：新口径全绿，但你无法证明判据本身是对的 —— **一个写反的判据同样会输出「全绿」**。

**实测**：一次方向类判据被写反（把「坐标值更大的一侧」当成某一面墙），首跑报「**36 件全部穿墙**」，连本来就正确的件也报错。修正后：**新口径 0 件、旧口径 3 件**，且那 3 件与用户所指**完全一致** —— 判据这才被证实。

**三条做法**

1. **判据旁写「两端各自是多少」**，不写方向词（「内侧 / 外侧 / 更北」）。**方向词是写反的温床**：写的人自己也在脑内换算。
2. **坐标系与换算关系写进代码注释** —— 例如导出后 `z = −y`，就要写明「更负侧」对应哪面墙，而不是留一句「北侧」让人二次推断。
3. ★★ **判据有效性靠「能在旧口径上复现原问题」证明**：拿**出问题的那一版**跑一遍复核脚本，症状要能**原样报出来**。**新版本全绿不能证明判据对**（写反的判据也会全绿）。

**★ 独立复核手段：不依赖建模软件**

复核脚本不必依赖宿主机上的建模软件，直接解导出文件块（如 GLB 的 JSON chunk）即可做三件事：

| 做什么 | 要点 |
|---|---|
| 导出物 ↔ 数据源**逐件**交叉比对 | 容差写明（如 2mm）；逐件列出偏差，不只报总数 |
| 判据检查 | 越界 / 穿墙 / 净空等 |
| **计数断言** | 节点 / 网格 / 材质 / 各名前缀件数 |

> 好处有二：**不会被「软件打不开」阻塞**；且与建模脚本**不同源**，才谈得上"独立"。
> ★ 读导出文件的一个必踩坑：导出格式的网格常是**归一化立方体**，尺寸靠节点 `scale` 表达 —— **只读 `translation` 会得到「所有盒子高 1.00m」的假盒子**，必须**乘 `scale` 并套旋转**。

## 五、Blender 无头模式踩坑清单（本流程实测）

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本里灯光/背景设置静默失效，画面全暗或全白 | 无头打开带世界节点树的 blend 时，`world.node_tree.nodes.get("Background")` 可能返回 `None`（节点树延迟生成） | `view_layer.update()` 后重取；仍无则清空节点树重建 Background+OutputWorld |
| 正交渲染取景轴不确定、画面偏移 | 正交相机默认 `sensor_fit=AUTO`，ortho_scale 对应轴随分辨率比例变 | 显式 `sensor_fit='HORIZONTAL'`，ortho_scale 即水平跨度 |
| 面光（AREA）打室内立面严重过曝 | 能量按瓦计算，小空间内 900W 量级全白 | 弃用面光，用"白色世界 1.0 + SUN 3.0"高角度太阳（模型无顶板时可越过墙顶照亮室内完成面） |
| 相机朝正南看，画面左右与世界 X 相反 | 面向南方时东在画面左侧，属正确镜像 | 标注/截图解读时按相机朝向换算，不要当 bug |
| 5.2 无 DAE 导入器 | 新版移除 | 参考层用 OBJ：`global_scale=0.0254, forward_axis='NEGATIVE_Y'` |
| CJK 标注文字乱码/缺失 | 无头环境无默认中文字体 | 文字对象显式指定系统中文字体（macOS：PingFang）；PIL 拼图用 Hiragino Sans GB |
| 渲染色彩发灰 | AgX/Filmic 视图变换 | 方案沟通图用 `view_transform='Standard'`，白底自发光背板置 z=-0.15 |
| 参数传不进脚本 | `--python` 与 blend 文件参数顺序敏感 | 渲染/导出类：`blender --background --python 脚本.py -- blend 参数…`；纯验收类可 blend 在前 |

## 六、交付前检查清单

- [ ] 每条标注端点已提取并落盘（数量与源模型标注总数一致）；
- [ ] 每个修订点至少有"标注/面片/目视"中两类证据；
- [ ] 几何 JSON 含 changes_vN 与 known_gaps_vN，坐标换算常数写入元数据；
- [ ] 旧版 JSON/blend/渲染图/说明全部保留，新版文件带 vN 后缀；
- [ ] 三进程验收 ALL_PASS，断言含对象总数、关键坐标、负向（已删构件）三类；
- [ ] 新旧俯视对照图编号与修订说明表格一一对应；
- [ ] 面积/净宽等下游数据按新几何重算并注明口径；
- [ ] known_gaps 给出"谁、何时、用什么动作复核"，不写"待确认"了事。

## 七、局限

- 本方法把实测源模型视为权威；若实测本身有误（漏测、测错），双证据会一起错——关键尺寸仍需现场抽检；
- 面片聚类参数依赖源模型建模习惯（图层、分组、是否布尔开洞），换项目需重调容差并人工复核簇归属；
- 完成面小进退（几十毫米的抹灰/包柱）在结构模型中按直墙+壁柱带表达，残余偏差进 known_gaps，不追求测绘级复刻；
- 产出仍是**方案推演模型，不是竣工图**，不能替代持证测绘与施工图。
