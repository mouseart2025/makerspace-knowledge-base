# 设备外观模型获取：图片生成 3D 与落位接入工作流

> **一句话**：甲方常常只给设备照片、不给 3D 模型。此时可用「图片生成 3D」工具把照片变成带贴图的 GLB，**当作外观与体量表达**用——但它**不能承载尺寸结论**，接入落位前必须过四道体检。

## 一、为什么规划阶段需要设备外观模型

纯用方块占位体做落位图，评审时甲方看不懂——**「这台是什么设备」这件事，方块表达不了**。而外观模型解决的是三件事：

1. **沟通**：甲方第一眼认出「这是我说的那台台架」；
2. **体量感**：高度、悬挑、展板、扶手这些特征会影响观感与遮挡判断，方块表达不出来；
3. **汇报素材**：方案图、汇报 PPT、网页预览都需要能看的设备形象。

★ **但它不解决「尺寸」问题**。尺寸、净空、面积账一律以项目自己的数据源为准（甲方规格表 / 工位要求）。这个边界见 §四、§五。

## 二、三条获得途径与选型

| 途径 | 从哪来 | 尺寸可信度 | 适用判据 |
|---|---|---|---|
| **A. 甲方提供三维模型** | 厂商/CAD 导出 | ★★★ 高（若与规格表一致则直接可用） | 首选。有就一定用，但**仍要与规格表交叉核对** |
| **B. 甲方只给照片 → 图生 3D** | 用本文 §三 的工作流自己生成 | ★ 低。**bbox 不可信**，只作外观表达 | 甲方无模型、但有实拍照片或产品图册时 |
| **C. 找库模型 / 素材站** | 通用 3D 素材库 | ★ 低。比例任意 | 有「某类设备的通用形象」即可、不需要认得出具体型号时 |

**选型顺序：A > B > C。** B 优于 C 的原因是：**外观是这台设备的外观**，甲方能认出来；C 通常只能表达"这有台机器"。

> 途径 B 的常见触发场景：甲方是终端用户而不是设备厂商，手里只有设备现场照片、产品宣传图或截图；采购还没下单，厂商资料拿不到。这时图生 3D 是性价比最高的一步。

## 三、图生 3D 工作流（以 Hyper3D Rodin 为例）

**工具**：[Hyper3D / Rodin](https://hyper3d.ai)（Deemos 出品，云端服务，无本地部署）。
选它作为示例的理由：**单图即可生成**、输出含 PBR 贴图、GLB 导出是原生支持项，且有 Blender 插件。同类商业工具（Tripo 等）逻辑相近，替换要点见 §3.4。

### 3.1 输入：甲方给的照片够不够用

厂商明确：**单张图即可生成，不要求规定姿势或拍摄角度；分辨率、构图、背景、光照、主体隔离都是"可选拍摄建议"，不是提交要求**（来源：Hyper3D 官方 FAQ，2026-09-22 核）。

实践建议（能把质量拉高一档）：

- **优先选「能看清主体轮廓」的视图**——正立面或 3/4 视角比俯视、局部特写好；
- 设备在画面里**占比越大越好**，背景杂物少；
- 有多角度时**可选补充视图**，但不要用差异极大的视角（会造成几何互相矛盾）；
- **不要指望照片里的文字**：所有 3D 生成工具都在**表面文字**上翻车（厂商评测亦承认"struggles with legible text on surfaces，建议外部贴标"）。设备铭牌、参数表、教学展板上的字**必然糊**，这是预期内的，不是失败。

### 3.2 生成参数

| 参数 | 选项 | 建议 |
|---|---|---|
| 贴图变体 | **Shaded** / **PBR** | **要 PBR**。PBR 输出 albedo + roughness + metalness + normal 贴图，在渲染器里受光正确 |
| 网格密度 | Raw（约 500–1,000,000 面，默认 500k）/ Quad | 空间规划用 **Raw 且压低面数**；单件 10 万面级够用，全屋几十件装配后才跑得动 |
| 贴图分辨率 | 随套餐（Creator 起有 HD 与烘焙法线，Business 4K） | 规划用图 **2K 足够**（2048²），4K 白白拖慢装配 |

### 3.3 导出：为什么是 GLB、为什么会有两个文件

- **导出 GLB**：`glTF` 家族的二进制版，单文件打包几何 + 材质 + 贴图，是**同时能被 Blender / 网页 model-viewer / AR 直接消费**的格式（见 [三维模型网页发布与飞书归档-model-viewer工作流.md](../06-资源索引/三维模型网页发布与飞书归档-model-viewer工作流.md)）。厂商支持的导出格式还包括 FBX / OBJ / STL / GLTF / USDZ。
- **`base_basic_pbr.glb` 与 `base_basic_shaded.glb` 是同一份几何的两种贴图变体**：
  - `pbr`：3 张 2048² 贴图（diffuse / metallic-roughness / normal），体积大；
  - `shaded`：1 张 baked 贴图，体积约小 40%，**几何完全一致**。
  - → **入库取 pbr，给不会调材质的环境（简易预览、快速交付）备 shaded**。两者不要同时进场景，否则同一件设备被表达两遍。

### 3.4 换其他工具时的替换要点

替换工具只改三处：① 导出格式必须含 **GLB**；② 材质必须是 **PBR** 而非只有烘焙色；③ 输出必须能**指定面数上限**。其余流程（§四 体检、§五 归位）与工具无关。

## 四、★ 接入落位前的四道体检（本文最值得带走的部分）

图生 3D 的产物**在几何上是"看起来像"，不是"量出来对"**。四道体检做完再入库。

### 4.1 尺寸体检：bbox 不能当规格 ★

**厂商会宣称输出「稳定的真实世界尺度」**（来源：Hyper3D 官方 FAQ）。这句话的意思是**比例自洽**（不会一轴拉长），**不等于等于你这台设备的规格**。

**实测反例**：把生成模型与设备规格表外形逐一比，得到的三轴比值是 **×1.156 / ×1.100 / ×1.056**——**三轴不一致**。

**判据（一步定性）**：

| 现象 | 结论 |
|---|---|
| 三轴比值**不一致** | **资产本身尺寸不符**，不是尺度问题 → 只能归位缩放，不能靠改单位修 |
| 三轴比值**一致**（同一个系数） | **单位/缩放问题** → 改单位设置即可，几何本身是准的 |

★ 这条判据的价值：它把"要不要重做模型"变成一个**可计算的是非题**，而不是靠感觉。

### 4.2 单位体检：`.blend` 的 `scale_length` 与几何口径是否自洽

导入前**必查** `bpy.context.scene.unit_settings.scale_length`。

glTF 以**米**为单位，导入器会按该值换算。如果项目 `.blend` 的几何按「1 BU = 1 m」建、而该值被写成了 `0.001`，那么**任何导入都会放大 1000 倍**（实测：1,734.5 mm 的模型导进来变成 1,734,489.6 mm）。

- 根治：把 `scale_length` 改回 `1.0`（纯元数据订正，不动一个顶点）；
- 兜底：导入脚本里显式乘回 `UNIT = scene.unit_settings.scale_length` 再烘焙进网格。

### 4.3 朝向体检：哪个面是"操作面"

落位数据源里通常有 `face` 字段（朝 N/S/E/W）。要判断生成模型**本地坐标的哪个方向对应设备的正面**：

- 看**特征件**：教学展板、控制面板、扶手、液压杆——它们在哪一侧，哪一侧就是"背面/侧"；
- 定 `rot_z` 时注意：**若要做非等比归位缩放，`rot_z` 只允许 0° 或 180°**（90°/270° 与三轴不等缩放组合会错轴）；
- 校核方式：落位后**从世界坐标反算包围盒**，与落位矩形的四边逐一比。**不要只看缩略图**——"几何存在但朝向反了"在缩略图上极难发现。

### 4.4 体量体检：面数、双重表达与遮挡

- **面数**：图生 3D 产物是密集三角网格（数十万面级）。单件没问题，**几十件装配后预览会卡**。入库前先减面。
- **双重表达**：脚本画的占位盒与真实外观**不可同时可见**，摆好后必须把占位盒 `hide_render = True`。
- **渲染遮挡**：设备的近景校核图要**隐掉墙体/包管/门窗**（否则近侧外墙把室内全挡死），但**必须留柱**——柱是图纸与模型的共同锚点。

### 4.5 ★ 重跑体检：输入必须是干净基线，脚本必须幂等清场（2026-09 增补）

**症状**：重跑一遍落位脚本，产物**体积翻倍**、对象数正好是两倍 —— 脚本正常跑完、打印「完成」，产物却是错的（属「**成功语气 ＋ 错误内容**」那一族）。

**实测**：重跑后 GLB **2.47MB → 3.45MB**；对象数 **584 → 836**；落位对象前缀计数为 **72**（期望 36）；描边件 **288**（= 36 × 8）。

**根因**：把**上一轮的输出**当成了输入 —— 落位脚本是「往场景里加对象」，**自己没有清场逻辑**。

**三条对策**

1. **认准干净基线**：基线里该为 0 的计数必须真的是 0。排查手法 = 用宿主程序**逐个候选文件打印关键前缀计数**，**别靠文件名猜**（`*_plan_*` 一类往往是**输出**，`*_native_vN` 才是干净基线）。
2. **脚本补幂等清场**：按**对象名前缀白名单**先删后建；该前缀必须与「建筑构件」（墙 / 窗 / 门框 / 柱 / 分区）**严格不重叠**。
3. **写完断言计数**：对象数 / 网格数 / 各前缀计数逐个比对，**不等就报错退出**。

## 五、归位缩放三条路线（各自代价，须明确取舍）

三轴比值不一致时（§4.1），必须选一条：

| 路线 | 做法 | 代价 | 何时用 |
|---|---|---|---|
| **A. 三轴各自归位缩放**（推荐） | 三轴分别缩放到数据源的目标外形尺寸 | 非等比形变（本例三轴差 5%–16%）。**近看能看出来** | 落位/净空/面积账口径必须唯一 —— 这是默认 |
| B. 等比缩放 | 以长边（或占地对角线）为准等比缩放 | 另一维填不满包络（本例高矮约 9%） | 形变不可接受、且能容忍"缩在包络里" |
| C. 不缩放 | 保持原比例，纯外观示意 | 模型会**越出落位矩形**，可能压住墙或通道 | 只做"看一眼"的示意，不作任何尺寸依据 |

★ **无论选哪条，都要在交付说明里写明**：这一件的尺寸依据是**数据源**，外观模型是**缩放后的近似**。否则下游会拿 3D 图去量尺寸。

## 六、踩坑清单

| 现象 | 原因 / 处理 |
|---|---|
| 导入后模型比屋子大 1000 倍 | `.blend` 的 `scale_length` 与几何口径不一致，见 §4.2 |
| 导入后立刻读 `matrix_world` / `dimensions` 得到荒谬的值 | 没有调 `view_layer.update()`。**导入后先 update 再读变换**；设完 scale/location 再 update 一次才读 `dimensions` |
| 缩放因子算出来是 0.0009 这种数 | 同上；或被 §4.2 的 1000 倍污染了基数 |
| 展板/铭牌上的字全是糊的 | **预期内**，见 §3.1。文字请自己在 Blender 里补标注（并注意 FONT 对象不进 glTF，导出前要转网格） |
| 同型多件摆完只剩一件 | 落位数据源可能**没有单件序号字段**，同名对象互相覆盖 → 按出现顺序自己编号 |
| 正交俯视图里中文标注横过来了 | 相机用 `to_track_quat` 在仰角≈90° 附近会翻滚 90° → 改用显式 `rotation_euler = (0,0,0)` |
| 中文字体加载失败 | 不要写死某一款字体路径。用回退链（macOS 实测：`PingFang.ttc` 可能不存在 → `STHeiti Medium.ttc` → `STHeiti Light.ttc` → `Songti.ttc` → `Supplemental/Arial Unicode.ttf`） |
| 网页/AR 里模型位置飘 | Y-up 与毫米→米换算，见 [三维模型网页发布与飞书归档-model-viewer工作流.md](../06-资源索引/三维模型网页发布与飞书归档-model-viewer工作流.md) §三 |
| 重跑落位后模型「翻倍」、文件大小暴涨 | 拿了**上一轮输出当输入**，脚本无清场逻辑 → 见 §4.5 |
| 独立复核读导出文件时，包围盒对不上 | 导出格式的网格常是**归一化立方体（±1）**，尺寸靠节点 `scale` 表达、`translation` 只负责定位 → **只读 `translation` 会得到「所有盒子高 1.00m」的假盒子**，必须**乘 `scale` 并套旋转**；另：旋转表示若与赋值方式不匹配（如把欧拉角赋给四元数模式）会被**静默忽略** |

## 七、适用边界与权利风险（不夸大）

**能做的**：体量感、外观识别、汇报素材、遮挡/观感的定性判断。

**不能做的**：
- ✗ **不能作为尺寸依据**——规格、净空、面积账一律走数据源；
- ✗ **不能作为采购对标**——图生 3D 是"像"，不带型号与参数；
- ✗ **不能表达内部结构**——只是外壳，检修空间、开门方向、管线接口都表达不出来；
- ✗ **不适合表达可动件**（液压杆、门扇、翻转台面）——需要拆成"本体 + 可动件"分别处理。

**权利风险两条（务必写进交付说明）**：
1. **商用权利随套餐**——免费层通常带水印且不可商用，商用授权从付费层起。**方案里用到的每一件都要确认它是在有商用授权的账号下生成的。**
2. **纯 AI 生成的资产版权主张很弱**——无实质人工编辑时，多数法域不给予版权保护。若成果要对外发布，**建议保留人工编辑（减面、改名、补标注、调材质）**，既强化主张，也是质量需要。

★ 另注意：**素材本身不要复制进本库**。第三方工具的产出与界面都受其条款约束，本库只记录**方法与踩坑**，并给出外链。
