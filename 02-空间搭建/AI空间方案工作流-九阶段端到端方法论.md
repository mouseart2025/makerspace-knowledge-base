# AI 空间方案工作流：从需求到 3D 方案与决策

> 内化时间：2026-09 ｜ 验证场景：职业院校多专业共享创客空间（L 型、数百平米级、硬装已完成、楼上为宿舍）
> 定位：本文是 `02-空间搭建/` 规划类文档的**工程落地篇**——前四篇解决"规划怎么做、AI 怎么用"，本篇解决"怎么把规划真正做成工程交付物"。

## 一、为什么需要这套方法论

空间规划项目有三个老毛病：

1. **"全达标"幻觉**：方案文档写"全部满足"，但落位后第一次体检就查出致命问题
2. **决策靠感觉**："差不多就行"——评审过不去也说不清差在哪
3. **改一处坏一片**：动一个设备压了通道、堵了门洞，要回炉重做

**根因是同一件事**：判断靠"看图 + 估算"，不靠"算出来 + 复算"。

**实证**：某真实项目首轮方案落位后，第一次量化体检查出 20+ 项问题（含多项致命），而此前所有方案文档都写着"全部达标"。

### 三条铁律（贯穿全篇）

| 铁律 | 含义 | 违反的代价 |
|---|---|---|
| **① 单一数据源** | 设备清单同时驱动落位与检查，禁止两处维护 | 改完一处忘改另一处，几何与检查对不上 |
| **② 可复算优于可描述** | 距离、面积、净宽必须由代码算出，不写"约 15m" | 致命问题被估算掩盖 |
| **③ 版本即资产** | 现有文件永不覆盖，修订另起版本号 | 历史不可回溯，复盘无据可依 |

## 二、九阶段流水线

```
S0 需求对账 ─► S1 底图矢量化 ─► S2 基础模型 ─► S3 构件建模
                                                    │
                                                    ▼
S9 交付 ◄─ S8 知识库审查 ◄─ S7 量化体检 ◄─ S6 自动落位 ◄─ S5 设备清单 ◄─ S4 分区动线

反馈回路（重要）：
  QA 不过                    → 回 S5 改数据（不是改模型）
  知识库审查出结构性缺口      → 回 S4 改分区
  甲方需求变更               → 回 S0 重对账
```

**分组**：读需求（S0~S1）→ 建 3D 草图（S2~S3）→ 设计（S4~S5）→ 验证（S6~S8）→ 交付（S9）

## 三、九阶段逐个拆解

> 每节格式：**目标 → AI 做什么 → 人做什么 → 产出 → 判据 → 工具 → 常见死法**。

### S0 需求对账

| 项 | 内容 |
|---|---|
| 目标 | 把甲方模糊需求变成可执行的设备清单输入 |
| AI 做 | 解析甲方文件（DOCX/XLSX/PDF/MD），抽取「设备名 + 数量 + 尺寸 + 工位要求」 |
| 人做 | 复核：哪些是**采购清单**（带预算、有约束力）、哪些是**课程建设方案**（带面积、无台数）、哪些是**建议稿** |
| 产出 | 需求矩阵 + `设备需求清单对账表-vN.md`（每条标注来源） |
| 判据 | **设备必须以甲方需求文件为准，禁止功能推定凭空加设备**（红线 1） |
| 工具 | python-docx / openpyxl / PyMuPDF |
| 死法 | **最致命**：AI 自行补充"看起来应该有"的设备。某项目一次凭空加 13 台（约 22 ㎡），同时删掉了 3 项真实设备 |

### S1 底图矢量化

| 项 | 内容 |
|---|---|
| 目标 | 把 CAD/PDF 平面图转成可代码读取的矢量坐标 |
| AI 做 | 验矢量 PDF → 按颜色/线宽分类路径 → clipPath 裁剪 → 转 SVG + 提取坐标 |
| 人做 | 校核区域边界（**不要把尺寸标注线当成区域分界**） |
| 产出 | 矢量底图 `.svg` / `.html` |
| 判据 | 区域边界 + 门 + 柱 + 窗全部矢量化；尺寸标注单独图层 |
| 工具 | 见 [AI平面图理解与矢量提取方法论.md](../06-资源索引/AI平面图理解与矢量提取方法论.md)（5 步法） |
| 死法 | 把尺寸标注线当成区域分界 → 区域边界全错 |

### S2 基础模型（3D 草图·第一关）

| 项 | 内容 |
|---|---|
| 目标 | 用 Ruby + MCP 把矢量底图变成 SketchUp 体块 |
| AI 做 | 读 SVG → 算外轮廓 → `add_face` + `pushpull` |
| 人做 | 验证活动模型（`--expect` 锁）；目视第一版 |
| 产出 | `*_基础模型_vN.skp`（**永不改，覆盖 = 回炉**） |
| 判据 | 体块无遗漏墙段、层高正确、与平面图重叠目视一致 |
| 工具 | SketchUp + MCP `eval_ruby`（见 §四、§五） |
| 死法 | 三条命门（单位 / 坐标 / 法线），见 §四.4 |

### S3 构件建模（3D 草图·第二关）

| 项 | 内容 |
|---|---|
| 目标 | 在体块上装柱、门、窗 |
| AI 做 | 从几何扫描拿真实柱表 → 两柱居中算法放窗 → 穿孔墙法开窗洞 |
| 人做 | 校核柱位（**实测优先于平面图记录**）；门窗功能净空判定 |
| 产出 | `*_窗体_vN.skp` → 冻结为设计基线 |
| 判据 | 柱/窗/门全部就位；玻璃真透明；门洞无窗台堵门 |
| 工具 | 数据驱动生成器（幂等）+ 窗体定位方法论 |
| 死法 | ① 布尔减运算不可用 → 用穿孔墙法 ② 玻璃材质不可靠 ③ 只设正面材质 ④ 门洞没作为"洞"参与 |

### S4 分区动线

| 项 | 内容 |
|---|---|
| 目标 | 把空间划成功能区 + 定骨架通道 |
| AI 做 | 按邻接矩阵 + 面积配比生成 2~3 个候选分区方案 |
| 人做 | 选定主入口；接受或否决候选；标**三带分区**归属 |
| 产出 | 分区方案文档 2~3 份 + 骨架通道定义 |
| 判据 | 主脊柱净空；各区主通道贯通；**spine-first 排布** |
| 工具 | 见 [创客实验室规划方法论与全流程.md](创客实验室规划方法论与全流程.md)（六阶段模型、需求→能力映射、量化决策工具） |
| 死法 | **按设备类型分区**（数控区/无人机区/教学区）而非**按危险等级**（安静/中噪/高噪多尘） |

### S5 设备清单（数据层）

| 项 | 内容 |
|---|---|
| 目标 | 把 S0 需求变成 Python 数据源 |
| AI 做 | 继承上一版 → 改尺寸修正表 + 坐标重排表 + 未落位大件清单 |
| 人做 | **逐台核对**：尺寸是否按甲方规格表？"工位要求"是否含操作空间？ |
| 产出 | `设备清单_方案N_vN.py`（单一数据源） |
| 判据 | 与 S0 对账表 100% 对得上；尺寸优先取甲方规格表 |
| 工具 | Python 模块：`EQ`（设备）/ `SHOWCASE`（去重样板）/ `PENDING`（未落位）三段式 |
| 死法 | **继承陷阱**：`from 旧版 import *` 后覆写常量，但继承的函数仍读旧模块全局 → 必须 def 重写 |

### S6 自动落位（3D 草图·第三关）

| 项 | 内容 |
|---|---|
| 目标 | 把数据源设备摆到 3D 模型里 |
| AI 做 | 落位脚本跑：设备组 + 骨架 + 梁 + 标签 + 样板阵列 |
| 人做 | 锁活动模型；指定中文字体；目视复核 |
| 产出 | `*_方案N设备落位_vN.skp` + 顶视图/鸟瞰图 |
| 判据 | 落位前预检（不越界/不穿墙/不压窗）；落位后 QA 致命 = 0 |
| 工具 | `MCP设备落位_vN.py`（支持 `--plan / --version / --expect / --font`） |
| 死法 | **可达性病灶**：列间通道需 ≥1500mm 才稳。留 1000mm 时，任何一台设备侵入 100mm 就会跌破 950mm 硬门槛，导致整列不可达 |

### S7 量化体检（QA）

| 项 | 内容 |
|---|---|
| 目标 | 多类指标自动打「致命 / 严重 / 建议」三档 |
| AI 做 | 跑 QA 脚本：越界 / 重叠 / 柱碰撞 / 门洞净空 / 通道可达 / 疏散 / 利用率 / 容量 |
| 人做 | 接受"已确认风险"或要求修改 |
| 产出 | `方案N_布局体检报告-vN.md` |
| 判据 | **致命 = 0** 才可交付；严重 = 0 或有甲方书面接受 |
| 工具 | 栅格法（100mm）+ Chamfer 距离变换 + 多源最宽路径 Dijkstra 变体 |
| 死法 | **只查各区内部，漏掉区与区之间**。必须显式测**区际瓶颈矩阵**（全区间两两最宽路径的最小净宽） |

**关键判据参考值**（可按项目调整）：

| 指标 | 阈值 | 等级 |
|---|---|---|
| 越界 / 穿墙 / 重叠 / 压柱 | = 0 | 致命 |
| 设备侵占预设骨架通道 | = 0 | 致命 |
| 区际瓶颈净宽（最宽路径的最小净宽） | ≥1500mm（<900 致命） | 严重 |
| 主入口 → 各区瓶颈净宽 | ≥1500mm | 严重 |
| 路径绕行系数（路径长/直线距离） | ≤1.5 | 建议 |
| 通道净宽硬门槛 | **≥950mm**（不是 1000） | — |
| 各区设备占地率 | 15%~45% | 建议 |
| 工位数 vs 峰值同时就座需求 | 达标（轮换模型） | 严重 |

> **易错点**：主通道标准是**最小 1200mm / 推荐 1500~1800mm**。做到 1200 是"达最小"不是"不达标"。
> **易错点**：疏散"≤10m"通常是**项目自设目标**，通用规范是"≥2 个安全出口 + ≤30m"。报告必须澄清，否则甲方误以为是强制条文。

### S8 知识库交叉审查

| 项 | 内容 |
|---|---|
| 目标 | 用规范类文档补几何检查查不出的问题 |
| AI 做 | 拉知识库必查文档，逐条比对 |
| 人做 | 判定结构性缺口；接受或整改 |
| 产出 | 报告内「结构性缺口」章节 |
| 判据 | 至少显式处理 4 类缺口（见下） |
| 工具 | 知识库 `02-空间搭建/` 相关规范文档 |

**必查的 4 类结构性缺口**（几何全过 ≠ 方案可用）：

| 编号 | 缺口 | 依据 |
|---|---|---|
| **G1** | 未按**危险等级**分区（高噪多尘区与安静工位区直接相邻） | [设备摆放与布局规范.md](设备摆放与布局规范.md) §1.1：不要按设备类型分区，按噪音/粉尘/湿度分区 |
| **G2** | 教学/共创区容量不足 | [40人班制创客空间配置标准.md](40人班制创客空间配置标准.md) §2.2/§2.3/§5.3 |
| **G3** | 激光等高危设备**不靠外墙** + 排风未落实 | [设备摆放与布局规范.md](设备摆放与布局规范.md) §3.1：**排风需装修阶段预埋，不可后补** |
| **G4** | 仓储不足（标准 15~20%）、无安全区（PPE/灭火器/急救箱） | [创客空间规划与设计.md](创客空间规划与设计.md) §七 反模式 |

> 某项目实测：几何体检致命 0，但知识库审查发现 4 项结构性缺口全部命中。**几何指标过了不代表方案能用。**

### S9 交付

| 项 | 内容 |
|---|---|
| 目标 | 给甲方一份能拍板的文档 |
| AI 做 | 写甲方版报告（结论先行）+ 分析插图 + 多方案对比文档 |
| 人做 | 校对数据；明确推荐方案；附决策清单 D1~DN |
| 产出 | `方案N_布局体检报告-vN-甲方版.md` + 插图 + `多方案对比与选型建议-vN.md` |
| 判据 | 甲方不读历史版本就能看懂；每条决策都有数据支撑 |
| 工具 | matplotlib（中文字体需指定，如 PingFang SC） |
| 死法 | 把内部版本考古写进甲方版 → 甲方困惑。**交付稿必须清洗内部版本号** |

**多方案对比文档要点**（≥2 个方案时必出）：
- 硬指标横向对比表（统一口径，注明测量起点）
- **加权评分 + 权重敏感性分析**（标出"什么情况下 B 会反超 A"）
- **场景化推荐**（甲方看重不同 → 推荐不同）
- **共有问题清单**（换方案解决不了的，别让甲方指望选方案规避）

## 四、3D 草图专章（如何绘制三维草图）

### 4.1 为什么用参数化建模 + AI，而不是 AI 直接生图

| 维度 | AI 生图（扩散模型） | 参数化建模 + AI 脚本 |
|---|---|---|
| 几何精度 | 凭感觉，不可量 | 毫米级，可复算 |
| 可修改性 | 改一处要重画 | 改数据自动重生 |
| 评审可信度 | 意向图 | 工程图（可量、可裁、可碰撞检查） |
| 适合场景 | 概念意向、效果图 | 设备落位、通道净宽、疏散距离 |

**判断**：方案评审阶段必须用参数化建模出工程级 3D 草图；效果图另说。

### 4.2 技术栈

```
CAD / PDF ──► 矢量解析 ──► 矢量 SVG + 构件坐标
                                │
                                ▼
                    脚本语言 + MCP 通道（本地 TCP + JSON-RPC 2.0）
                                │
                                ▼
                        SketchUp（或其他支持 API 的建模软件）
                                │
                                ▼
                        落位模型 + 截图（顶视 / 鸟瞰）
```

**MCP 通道要点**（以 SketchUp 为例，详见 [SketchUp自动化与AI设备自动摆放-工作方法与踩坑记录.md](../06-资源索引/SketchUp自动化与AI设备自动摆放-工作方法与踩坑记录.md)）：
- 4 字节大端长度前缀 + JSON-RPC 2.0
- 核心工具：`eval_ruby`（执行任意脚本）/ 截图 / 模型信息查询
- Python 侧封装：`MCP.ruby(code)` / `MCP.screenshot(preset, path)`

### 4.3 三层建模法

```
Layer 1  体块层   基础体块（永不改）
Layer 2  构件层   柱 / 墙 / 门 / 窗（验收后冻结为设计基线）
Layer 3  设备层   设备组（每方案每版另存）
```

**铁律**：每一层只往上一层加，不改上一层。体块层**只读**，落位一律另存新路径。

### 4.4 三条命门（必查）

| 命门 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **单位** | 坐标差 25.4 倍 | 建模软件内部用英寸 | 所有坐标显式转长度单位（如 `x.mm`） |
| **坐标轴翻转** | 设备跑到镜像位置 | CAD 与建模软件 Y 轴方向相反 | 统一翻转公式；**只翻转区域位置，区内偏移保持建模软件约定** |
| **面法线** | 拉伸方向朝下 | 面朝向反 | 拉伸前检查法线方向，必要时反转 |

**典型坑**：把"毫米浮点数"直接喂给建模 API 的 `add_face`，被当成英寸解释 → 25.4 倍错位。**混合使用"数值坐标"和"带单位坐标"两条路径时极易中招。**

### 4.5 无法真开洞时的替代：穿孔墙法

某些建模环境的布尔减运算经 API 调用**返回切割体本身而非差集**，无法做真穿透洞。

**替代方案**——把"有窗的墙段"拆成三件重建：

```
窗台条   z[0, 窗台高]
窗楣条   z[窗顶高, 层高]
窗间竖肋 z[窗台高, 窗顶高]    ← 只在窗与窗之间留墙，窗位处无墙 = 真洞
玻璃组件 双面材质 + 透明纹理，落在墙线上
```

**门洞必须作为"洞"参与生成器**（否则会留下窗台把门堵住）。

### 4.6 标注与编号桥（让 3D 可读）

**三层标注**：

| 层 | 内容 | 用途 |
|---|---|---|
| 构件级 | 柱 / 窗 / 门 标签 | 校核建筑构件 |
| 设备级 | `区-型号-实例`（如 `E-19-3`） | 定位单台设备 |
| 样板级 | `S{号} 名称 尺寸 ×数量` | 去重样板阵列 |

**设备-样板编号桥**：看到 `E-19-3` → 找 `S19` → 知道是什么设备。**S 号牌跨方案通用**（同一设备在多个方案里都是同一个 S 号），评审时可跨方案对照，只是"区"前缀随分区归属变化。

**中文字体坑**：部分建模环境默认字体不支持中文 → 渲染成方块/乱码。
- 必须**显式指定中文字体参数**
- 建议**字体探测回退链**（首选 → 备选1 → 备选2 → …），避免换机器就乱码

### 4.7 截图验证闭环

**坑**：截图接口可能**强制预设视角方向**，无视脚本设置的相机。

**正确做法**：
1. 用预设给方向（顶视 / 轴测 / 前视 / 右视）
2. 关闭自动缩放（`zoom_extents: false`）
3. 脚本先框定目标范围，再截图

**每次落位必拍 2 张**：顶视图（看分区/通道）、鸟瞰图（看空间关系）。

### 4.8 基线冻结

**什么时候冻结**：当一份「体块 + 构件 + 标注」通过脚本复核后（构件数量、墙段范围、材质正反面、坐标与数据源零偏差），**立即冻结**。

**冻结动作**：
1. 算 MD5 写入元数据
2. 复制到只读归档目录
3. 设为只读权限
4. 写校验脚本（MD5 + 权限 + 数据一致性）
5. **每次开工前必跑**，输出「基线完好」才能继续

> 这条在多人/多轮次项目里价值极高：一旦基线被覆盖，所有后续模型全废。

## 五、人在环路：AI 不能自作主张的 7 条红线

| # | 红线 | 谁拍板 | 违反案例 |
|---|---|---|---|
| 1 | **设备清单以甲方需求文件为准**，AI 不得功能推定 | 人（核对对账表） | 凭空加 13 台无依据设备（约 22 ㎡），同时删掉 3 项真实设备 |
| 2 | **基线模型只读**，AI 不得覆写 | 脚本锁 + MD5 校验 | 一旦覆盖，所有后续模型全废 |
| 3 | **现有文档不直接修改**，修订另起版本号 | 人（按命名规范） | 就地改 v0.1 → v0.2 会丢失历史 |
| 4 | **规范条文 / 消防 / 疏散标准** AI 不得编造出处 | 人（核条文，注明"自设目标"vs"通用标准"） | 把项目自设的 10m 写成规范强制 |
| 5 | **价格 / 单价** 库里没有就说没有 | 人（查库或询价） | 编造隔断单价 |
| 6 | **3D 文字必带字体参数** | 强制显式指定 | 中文渲染成方块 |
| 7 | **多方案并列评审**，AI 不得"顺便淘汰"某个方案 | 人（出对比文档 + 权重敏感性） | AI 单方面删除有硬伤的方案 |

## 六、投入产出实录（学习曲线）

同一套流程跑三个方案，版本数对比：

| 环节 | 方案 1（首轮，摸方法） | 方案 2（复用方法） | 方案 3（方法成熟） |
|---|---|---|---|
| 体块模型 | 13 版 | 复用 | 复用 |
| 窗体/构件 | 10 版 | 复用 | 复用 |
| 数据源（设备清单） | **19 版** | 3 版 | **1 版** |
| 落位（3D 摆放） | **18 版** | 1 版 | **1 版** |
| 甲方版报告 | 9 版 | 1 版 | 1 版 |
| **小计** | **69 版** | **5 版** | **3 版** |

**核心洞察**

- **第一个方案付 69 版学费**：方法论 + 数据 + 几何 + 报告格式同时在学
- **第二个方案 5 版**：复用已沉淀的规律（见下）
- **第三个方案 3 版**：方法论成熟，**数据源 + 落位各 1 版一次通过**
- **边际成本递减 10 倍以上**

**已达成的可复用规律**（跨方案复用成功）：

| 规律 | 说明 |
|---|---|
| 纵臂多带式列位 | 每列必须有一侧贴贯通通道（否则整列不可达） |
| Spine-first 排布 | 先划骨架通道作不可侵占负空间，再往两侧填设备 |
| 设备-样板编号桥 | S 号牌跨方案通用，评审可对照 |
| 穿孔墙法 | 体块层固化后长期复用 |
| 字体探测回退链 | 换机器不乱码 |
| 三带分区法 | 按危险等级而非设备类型分区 |

> **预期**：下一个新项目，方案 1 应该 ≤30 版（而不是 69 版）。

### 过程中（决策点）

- [ ] **S0**：甲方文件按"约束力等级"分类，对账表每条标注来源
- [ ] **S2**：活动模型锁跑通；MD5 校验脚本就绪
- [ ] **S3**：构件层验收后立即冻结（只读 + 归档）

- [ ] 关键截图进插图目录，供后续报告复用
- [ ] 经验写入项目记忆（日志 + 长期笔记）
- [ ] **铁律回顾**：本项目违反了哪几条？代价量化记录，下次避免

## 九、已知局限（不隐瞒）

1. **设备尺寸**多为估算或甲方规格表，厂商手册到手后所有几何结论需重算
2. **栅格法 + 距离变换**测通道净宽有约 ±5% 误差，阈值需按 0.95 折算
3. **柱位**来自模型几何扫描实测，未与结构图二次校核
4. **未自动化检查**：门口疏散缓冲区占用、排烟路径、噪音传播、多班并发动线
5. **截图接口**可能强制预设视角，自定义相机有 workaround 但不优雅
6. **价格 / 工期 / 规范条文**不在本方法论范围内，必须由甲方或设计师现场核定
