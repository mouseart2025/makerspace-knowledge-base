# 实景三维重建：AI 驱动 Blender 原生建模工作流

> 把**实景空间扫描产物**（网格模型、点云、全景图、CAD）交给一个能读本地文件、能执行命令的 AI 编程智能体，让它在本机驱动 **Blender**（Python 接口 `bpy`）重建出**墙、地、顶、门、窗各自独立、可继续编辑**的原生三维空间，而不是只能看不能改的"扫描壳子"。
> 来源：开源案例仓库 [realsee-developer/realsee-astra-blender](https://github.com/realsee-developer/realsee-astra-blender)（如视 Realsee 官方开发者仓库，代码/提示词/原创文档为 MIT 许可；案例使用 Codex 中的 GPT-6 Astra + Blender 5.2.1 LTS）。本文提炼其方法论与提示词资产，并给出在创客空间改造项目中的落地建议。

## 一、方法是什么

### 1.1 核心思路

传统空间扫描（如如视 Realsee 的 VR 全景）交付的是**在线浏览体验和一整块三角网格**：能逛、能看，但无法单独选中一段墙改厚度、换一扇门、调一种地面材质。本方法把扫描的**附加导出产物**当作"证据"，让 AI 智能体像建模员一样在 Blender 里**从零搭一个原生场景**：

```
Realsee（或其他来源）导出产物
  ├─ CAD / 平面图     ── 约束尺寸、墙线、门窗位置 ─┐
  ├─ 点云 E57 / PLY   ── 约束三维形态与空间比例   ├─► 多源证据交叉验证
  ├─ 全景 / 六面图    ── 约束外观、材质、灯光     ─►      ↓
  └─ 带贴图扫描网格   ── 整体形状参考（默认隐藏） ─┘   AI 智能体驱动 bpy
                                                       ↓
                              Blender 原生场景（墙/地/顶/门/窗分件可编辑）
                                   ├─ 同机位对照渲染（现场 vs 模型）
                                   ├─ 保存 → 重开 → 实际编辑验证
                                   └─ 扩展：漫游动画 / USDZ（带物理）/ 网页 GLB
```

### 1.2 案例规模（公开仓库的真实数据，可作工作量预期锚点）

| 项 | 数据 |
|---|---|
| 案例空间 | 走廊、服饰/摄影展示室、小酒吧、桌足球游戏室、客餐厅展示区（约 87.25 ㎡，平面约 13203×9730 mm，净高标注 2470–3021 mm） |
| 原始资料 | 396 个文件、6,079,895,800 字节（约 5.66 GiB；其中 8 张 RAW 全景约 4.42 GiB） |
| 全景站位 | 8 个（注意：**8 个站位 ≠ 8 个房间**，房间划分须以配准后的资料为准） |
| 最终产物 | 原生 `.blend`（252 MB）、漫游工程（252 MB）、85 秒漫游视频（44 MB，24 fps、1280×720）、带刚体/碰撞的 USDZ（560 MB）、网页 GLB（17.2 MB），合计约 1.13 GB |
| 公开代码 | 精选 60 个 Python 脚本 + 1 份漫游路线 JSON（案例专用，非一键流水线） |

> 以上数字随仓库发布版本可能变化，权威口径以仓库 `data/README` 与 `artifacts/manifest.json` 为准。

## 二、适用场景与边界

| 维度 | 适用 / 不适用 |
|---|---|
| **适用** | 已建成空间需要可编辑现状模型做改造推演；硬装已完成、要试不同布局/材质/动线；需要向甲方/团队做三维漫游汇报；要导出带物理的 USDZ 做进一步仿真，或导出 GLB 做网页展示 |
| **适用** | 手头有空间扫描/摄影测量产物（网格、点云、全景、CAD 任得数类，越全越准） |
| **慎用** | 需要测绘级精度、竣工图或施工图依据（模型精度受扫描质量制约，详见 §9） |
| **不适用** | 拿不到任何现状资料的纯空地新建项目（应走常规规划流程，见 [创客实验室规划方法论与全流程.md](创客实验室规划方法论与全流程.md)） |
| **不适用** | 只想要"一键出效果图"——本方法的价值恰在**可编辑原生模型**，需要人与 AI 多轮对照迭代 |

对创客空间改造的直接价值：硬装已完成场地（尤其本项目这类楼上有宿舍、约束多的 L 型空间）可以低成本获得"数字现状副本"，在其中试摆设备、验证门洞与动线、出漫游视频用于沟通，而不必在现场反复丈量。

## 三、输入：扫描产物的证据分工

### 3.1 Realsee 导出物清单与用途

如视一站式制作平台中，进入自己的 VR 项目，在预览页上方"下载中心"选择产物生成并下载。各类资料在建模中承担**不同的证据角色**：

| 下载什么 | 格式（案例） | 交给 AI 做什么 |
|---|---|---|
| 三维模型及贴图（基础版 + 高精度两档） | OBJ / FBX / glTF / GLB + JPG/PNG 贴图 | 了解整体形状；作为参考保留；**同空间多格式只建一份实体，勿重复导入** |
| 点云 | PLY、E57（E57 还含扫描站位、图像 GUID、位姿四元数） | 确定墙/地/顶位置与空间比例，约束真实三维形态 |
| 全景图 | 8 张全景 JPG + 每站位 6 张六面图（cube-map，共 48 张） | 看清外观、材质、灯光、区域连接；六面图用于判断真实形状 |
| RAW 原件 | 8 个 DNG | 必要时核查细节与曝光，不必全部导入 |
| CAD / 平面图 | `cad.dwg`、`cad.dxf`、示意平面图 PNG、6 张正交平立面图 | 理解布局、墙线、门窗位置、标注尺寸与净高 |
| 空间视频 | 原始 VR 视频 MP4 | 核查区域之间的连接关系 |

### 3.2 多源证据的分工原则（本方法的方法论内核）

| 证据源 | 约束什么 | 不能用来做什么 |
|---|---|---|
| CAD 标注/DXF 实体 | **尺寸**：轮廓、门窗、各位置净高 | CAD 块（BLOCKS）里的家具/卫浴/楼梯图例不代表现场实物，只有真实放置且有现场证据的才重建 |
| 点云 / 高模 | **实际三维形态**：墙地面位置、厚度、空间比例 | 点云有噪声、缺测，不能为凑漂亮数字删点或缩放 |
| 全景 / 照片 | **可见细节与外观**：材质、灯光、物件 | 全景投影的弯曲不是墙面真弯曲；不能按全景编号猜相机站位 |
| 正交图 / 平面图 | 核对与总览 | 平面 PNG 常用英尺英寸标注，与 CAD 的毫米制冲突时须统一（见 §6.2） |

**冲突仲裁纪律**：来源之间冲突时，要定位、量测、写明采信依据，不得为得到"整齐数字"而篡改比例、删点或忽略矛盾。镜子/玻璃中的倒影不得重复建成另一间房或额外物体。

### 3.3 资料整理的三条硬纪律

1. **保留完整目录结构**：模型与贴图的相对位置不能打散——案例中遇到引用外部贴图的 GLB，单独拿走模型文件会丢纹理。
2. **原始资料只读、原样保留**：实验输出写到 `output/`，分析记录写到 `research/`，二者不污染原始数据。
3. **逐文件建清单**：标明用途、对应区域、读取状态、重复关系；不得因格式不便而静默跳过某个文件（不导入场景 ≠ 不处置，每个文件都要有"用了/核验过/确认为重复"的记录）。

> 大文件通过 Git LFS 管理时，克隆后拿到的只是小文本指针，**必须拉取实体后才能建模**；可先只拉 CAD + 一种带贴图高模 + 全景，其余按需补拉。

## 四、工具链与环境准备

### 4.1 角色与工具

| 角色 | 说明 |
|---|---|
| AI 编程智能体 | 能读取项目文件、编写并运行脚本、调用本机程序的会话即可（案例为 Codex 中的 GPT-6 Astra；可替换为任何具备本地文件与命令执行能力的智能体）。MCP 只是操作通道之一，**不是完成任务的前提** |
| Blender | 本机安装的 Blender（案例版本 5.2.1 LTS）；智能体通过自带 Python 的 `bpy` / `bmesh` / `mathutils`，以后台方式 `blender --background --python 脚本.py` 建模与渲染，再打开真实 `.blend` 检查 |
| 准备工具 | Python 3.10+ 标准库即可运行，无需先装分析依赖 |
| 分析依赖（可选） | NumPy、SciPy、Pillow、Matplotlib、ezdxf；点云/RAW/姿态步骤另需 pye57、rawpy、pyquaternion；USD 阶段需 pxr；视频编码需 ffmpeg/ffprobe。注意：装在系统 Python 里的库**不会自动出现在 Blender 自带 Python 中** |

### 4.2 三个环境自检命令（值得照抄的做法）

仓库 `tools/project.py` 提供三个零副作用命令，正式建模前先跑：

| 命令 | 作用 |
|---|---|
| `python3 tools/project.py doctor` | 查找 Blender、读取版本，顺带报告 ffmpeg 是否在 PATH；Blender 不在 PATH 时可加 `--blender /可执行文件路径` |
| `python3 tools/project.py inventory` | 盘点 `data/`（文件数、总字节、格式统计），写出 `output/source-inventory.json`，不导入任何文件 |
| `python3 tools/project.py smoke` | 在全新临时目录建一段测试墙，**用三个独立 Blender 进程**依次完成：保存 → 重开并编辑 → 再重开确认编辑保住了 |

`smoke` 的设计思想直接呼应最终验收：**"保存后换进程重开、编辑还在"从环境阶段就开始验证**，而不是等几千个对象建完才发现可编辑性是假的。

### 4.3 项目目录约定

```text
我的空间建模项目/
├── data/        # 扫描导出资料，保留原文件夹结构，只读
├── output/      # .blend 检查点、渲染、最终工程（git 可忽略）
├── research/    # 配准、测量、清单等分析记录（git 可忽略）
└── scripts/     # 实际执行过的建模脚本（可复现凭证）
```

## 五、五阶段工作流

### 阶段 1　准备资料

按 §3 下载/整理扫描产物到 `data/`，保留目录结构；跑 `inventory` 建清单。用自己的空间时，让智能体通读资料后**先报告"这些资料各能用于什么、还缺什么"**，再决定补采。

### 阶段 2　环境自检与首次握手

先发一条低风险指令确认智能体能找到资料和 Blender：

```text
这是一个空间重建项目，原始资料都在 data/ 中。
请先看看有哪些文件，找到本机安装的 Blender，并检查能否调用。
用几句话告诉我这些资料分别能用于什么，以及还缺什么。
```

跑通后再正式建模。脚本、预览图、输出目录都可让智能体自行创建。

### 阶段 3　下达"建立可编辑空间"的任务（分阶段，不一次写满细节）

任务要点：**以空间主体为先**（房间布局、墙、地、顶、门窗、区域连接），家具小物在后；要求原生分件、保留可隐藏的扫描参考、每阶段存档、先出布局预览。可直接使用 §7.1 的提示词。

### 阶段 4　看预览、像对设计方案一样迭代

- **第一版先看俯视图（plan view），不是精致效果图**：隐藏顶面与家具，检查房间有没有漏、走廊是否连通、门窗位置对不对。
- 指出问题要**定位到区域 + 描述差异**，并要求"先结构、后装饰"，例如："摄影间通向走廊的位置，对照原始全景图再查；先修墙、开口和顶面的关系，再处理装饰细节。"
- 结构定稿后再转材质灯光，要求出**同机位对照图**：现场照片与渲染图并排（contact sheet），差异一目了然。
- 典型迭代话术："走廊太亮了""这个开口形状不对""保留布局，换一种墙面材质"。

### 阶段 5　交付、验证与扩展

- 最终工程保存为 `output/reconstruction_native.blend`；**必须从磁盘在新的 Blender 进程中重开**，并在临时副本上实际执行编辑测试（见 §6.6）。
- 扩展应用：复制工程试新配色出对比图；制作相机路线保留在工程内的漫游；导出 USDZ（可带刚体与碰撞）与网页 GLB。

## 六、核心方法论八条（全文最值得带走的部分）

### 6.1 原生可编辑性是硬指标，不是"能打开看"

| 要求 | 具体做法 |
|---|---|
| 一切最终可见对象为原生构件 | `.blend` 内可编辑的本地 Mesh、Curve、原生材质节点与合适的原生修改器；不依赖 MCP、网络或额外插件即可打开/编辑/渲染 |
| 合理分件、语义命名 | 墙、地、顶、门框、门扇、家具及可独立操作的部件各自独立；按楼层/区域/类别组织 Collections；**门框与门扇分开，门扇原点放在合页处**（才能绕合页真实转动） |
| 保留真实构造 | 真实厚度与开口；重要尺寸能通过几何/修改器/节点直接调整，而不是只能改一份外部生成脚本 |
| 允许的技术 | Boolean、Solidify、Bevel、Array、Geometry Nodes 按需使用，不强制堆砌 |
| 明确禁止 | 把整块三角扫描网格导入、减面、重命名就宣称"重建完成"；用占位盒、单视角贴片、全景球或自动生成的相似资产冒充最终成果；把三维结构烘焙成平面贴图（画作/标签等本就是平面图案的可用贴图，但其框架/承载物必须有真实几何） |

### 6.2 先统一尺度、坐标与单位，再动手建几何

案例中的典型坑与处理：DXF 头中 `$INSUNITS=4` 表示毫米，而平面 PNG 用英尺英寸标注，须统一到 Blender 的米制；不要按 glTF 后缀盲信坐标轴，也不要按全景文件编号猜相机位姿——E57 内含扫描/图像 GUID、四元数与平移，应优先核实；外部 JPG 与 E57 内嵌图像未证明字节级相同，须做内容与方向匹配后才能赋相机位姿。所有"源文件 → 场景"的变换、控制点都要保存记录。

### 6.3 结构优先、分阶段冻结

先全空间结构与主要物体，再细节与材质；每个有效阶段保存 `.blend` 检查点与可复现脚本。家具与小物最后做——先把空间壳子搭稳，再决定哪些陈设值得细做。俯视图的价值高于早期效果图。

### 6.4 每个对象都要有"身份证"和来源映射

建立房间/区域、墙段、门窗、固定构件、家具陈设的**覆盖清单与稳定对象 ID**，把来源、所在区域、推断状态（实测/推断/补全）写入对象自定义属性或可追溯映射。8 个全景站位要逐站位核对六个方向，避免漏掉天花、灯具、地面、门背面和转角。分辨率不足、遮挡或缺失区域要附来源、置信度与补全说明；重大几何缺口必须明确报告，**不得自行缩小清单去凑"100% 覆盖"**。

### 6.5 对照渲染是主要审查手段

按登记的相机位姿渲染多档视图（低成本 quick、结构、无材质 Solid、线框、俯视/立面、逐区域室内视图、与各扫描站位配准的相机视图），与源图排成对照。**隐藏扫描参考后复核**——不能靠底下垫着扫描层来遮缺件；只看一张美观渲染等于没验。

### 6.6 验收 = 新进程重开 + 真的动手改（而不是"看起来能改"）

交付前在**新 Blender 进程**重开最终文件，在临时副本上实际执行并保存/重开以下编辑：

1. 改变一段墙或一个开口的尺寸；
2. 绕合页旋转一扇门；
3. 单独移动一件家具并修改其材质；
4. 对复用扫描形状的代表性复杂资产，进 Edit Mode 修改局部几何再保存重开（仅"对象能移动"不证明可编辑）。

同时检查：缺失贴图、断链、异常法线、退化面、结构实体的非流形几何与明显穿插（布料/叶片等合法开放曲面不机械要求封闭）；关闭参考层后场景仍完整；材质资源已打包或用相对路径随工程交付。

**精度口径（案例自设目标，可借鉴但勿夸大）**：对可明确对应、无冲突的 CAD 标注尺寸，模型数值误差以 **≤10 mm 为建模目标**——这是建模对齐目标，**不代表扫描测量精度**；墙地顶等可靠表面要报告配准后的点云距离统计与采样方法，区分噪声、缺测与真实偏差。最终须列出关键尺寸的"参考值 / 模型值 / 差值"表。

### 6.7 多智能体并行的纪律

资料解析、物体识别、独立资产建模与审查可并行交给子智能体；但**主智能体统一尺度与集成，绝不让多个智能体同时写同一个 `.blend` 或控制同一个 Blender 场景**。

### 6.8 数据卫生、脱敏与权利分离

| 纪律 | 案例做法 |
|---|---|
| 原始资料保护 | 保留 `data/` 原文件与既有成果；所有实验在 output 副本上做 |
| 公开前脱敏 | 公开发布的模型中，现场二维码一律去除（纸张/包装保留几何、材质改纯色，含码贴图移除，视频局部遮罩） |
| 授权与权利分离 | 代码/提示词/原创文档 = MIT；扫描、照片纹理、画面中品牌与第三方素材的权利**不被 MIT 改变**；案例原始数据经所有者授权后才按原样公开（且明确说明其中**保留**现场二维码），公开模型则沿用已脱敏副本 |
| 私密资料不入库 | 其他项目/客户的私人导出未经授权与审查不进 Git；虚拟环境、缓存、凭据、中间渲染序列一律不提交 |

```text

（CAD、点云、扫描模型、全景图），并发现本地安装的 Blender。
```

### 7.2 详细任务书（Goal Prompt）的必备条款

仓库的详细版提示词以"目标模式"持久推进，要求智能体**不停在分析/计划/粗模/脚本交付阶段**，直到满足验收。提炼为以下条款，写自己的任务书时逐条覆盖：

1. **环境核查先行**：确认 `data/` 存在、逐文件建清单（用途/区域/读取状态/重复关系）；发现本机 Blender，不硬编码用户名或机器专属路径。
2. **尺度坐标**：解析 DXF 轮廓/标注/净高，与点云、高模、照片交叉验证；统一单位；保存全部变换与控制点。
3. **按证据重建**：建覆盖清单与稳定对象 ID；覆盖所有有证据的墙地顶、门窗门套、踢脚线、灯具、风口、开关插座及可辨识陈设；倒影不得重复建模。
4. **原生可编辑**：分件、命名、Collections、门扇原点在合页、真实厚度与开口；禁止整块扫描网格改头换面；参考集默认隐藏且隐藏后场景完整。
5. **材质**：可独立修改，正常 UV 与图片纹理；尽量分离照片中的照明与材质底色；三维结构不得烘焙成平面。
6. **持续执行与验收**：分阶段存档；多视角输出检查；交付前完成 §6.6 的重开实测编辑、尺寸差值表、几何健康检查与资源打包；未解决项清楚列出。
7. **授权与边界**：授权本地解析/建模/保存/渲染/验证，要求保护原始数据；禁止提交推送、上传资料、发布、采购或发外部消息；真实阻塞才提问，同时继续可独立完成的工作。

### 7.3 换成自己项目时的改写点

- 把案例的资料清单（8 站位、87.25 ㎡、具体房间名）替换为自己的 `inventory` 结果，让智能体**先读资料再自行列出**空间分区，而不是照抄案例房间。
- 没有点云时，任务书降级为"CAD + 全景 + 网格"证据组合，并显式要求标注哪些尺寸无法交叉验证。
- 只需要方案推演时，可把陈设覆盖要求降到"主要家具"，把精力集中在壳子与开口。

## 九、局限与风险（不夸大）

1. **不是一键复现流水线**：公开的 60 个脚本是**同一个具体空间**的案例代码，含场景专用对象名、坐标，且依赖未全部公开的 `research/` 测量 JSON、`output/checkpoints/` 旧场景与材质中间结果；正确用法是"让智能体参考其方法、针对自己的资料重新组织步骤"。
2. **脚本即顶层代码**：多数脚本在 import 时就开始工作、会写交付文件，不能批量 import 或当测试套件跑；须先读其输入/输出，在独立 Blender 进程中执行。
3. **精度非测绘级**：≤10 mm 是对 CAD 标注的建模对齐目标；扫描本身有噪声与缺测，成果不能替代持证测绘与施工图（与本库免责声明一致）。
4. **能力依赖智能体与环境**：方法要求智能体能稳定执行本地命令、长程推进并自我验证；任务书必须把"实际执行、不得只交计划/脚本"写成硬条款，否则容易停在分析阶段。
5. **数据权利与隐私**：扫描资料可能包含人脸、二维码、品牌、商业秘密；公开传播前须取得授权并脱敏；原始数据授权与代码 MIT 许可是两回事。
6. **版本时效**：案例基于 2026 年时点的 Blender 5.2.1 LTS 与 GPT-6 Astra/Codex；软件界面、命令与模型能力会变化，以官方当前文档为准。
7. **大文件成本**：原始资料 5.66 GiB、成果约 1.13 GB，LFS 缓存还需额外磁盘；团队协作要规划存储与 LFS 配额。

## 十、在创客空间改造项目中的落地建议

### 10.1 Blender 路线 vs SketchUp 路线（本库综合，供选型）

| 维度 | Blender + bpy（本文） | SketchUp + Ruby API（见[踩坑记录](../06-资源索引/SketchUp自动化与AI设备自动摆放-工作方法与踩坑记录.md)） |
|---|---|---|
| 软件成本 | 开源免费 | 商业授权（网页版/Pro 版） |
| 擅长 | 网格/点云处理、照片级渲染、动画漫游、USDZ/GLB 导出、把扫描壳重建成原生网格 | 建筑体块、参数化墙体门窗、与方案推敲流程贴合、上手门槛低 |
| 自动化接口 | Python `bpy`，后台无头执行成熟 | Ruby API + MCP `eval_ruby` |
| 典型选择 | 已有实景扫描、需要现状复刻/漫游/网页展示/物理导出 | 从平面图出发做方案体块与设备自动落位 |
| 可组合 | 二者并非互斥：Blender 负责现状复刻，导出的参考可进入方案建模流程 | 九阶段流水线 S2~S3、S6 的现成实现 |

### 10.2 推荐接入方式

1. **获取现状资料**：对已交付/在营空间约一次实景扫描（如 Realsee 服务），下载 CAD、点云、全景、网格四类产物；无点云时至少保证 CAD + 全景 + 带贴图网格。其他能产出点云/网格/全景的摄影测量或测绘手段（如本库[无人机测绘系列](无人机测绘实训区设计.md)提到的倾斜摄影/LiDAR 路线）同理可用，证据分工原则不变。
2. **接入九阶段流水线**：把产出的可编辑现状模型作为 S1~S2 的输入补充——图纸矢量提取解决"图纸怎么读"，实景重建解决"现场到底什么样"，两者叠合校验。
3. **先做最小验证**：只拉 CAD + 一种高模 + 全景，跑通 doctor/smoke，让智能体交出"只含墙地顶门窗"的第一版俯视图，再决定是否投入全量资料与陈设细节。
4. **审查重点对齐本库规范**：模型中的门洞净宽、通道宽度、区域面积，对照[设备摆放与布局规范.md](设备摆放与布局规范.md)与[40人班制创客空间配置标准.md](40人班制创客空间配置标准.md)的硬指标做量化体检；模型用于沟通，承重/电气/消防等仍以持证机构核定为准。
5. **资产沉淀**：把实际跑通的提示词、脚本与检查清单回写本库（可补充到 [AI辅助创客空间规划-方法与工具库.md](AI辅助创客空间规划-方法与工具库.md)），形成柴火自己的"扫描→重建→方案"模板。
