## 一、为什么用 AI 做创客空间规划

### 1.1 现状数据

- **只有 27% 的 AEC（建筑/工程/施工）企业**目前在业务中使用 AI；早期空间规划是 AI **立即能交付价值**但最未被覆盖的环节["https://www.snaptrude.com/blog/ai-space-planning-at-department-level-design-the-bubble-diagram-that-actually-connects-to-bim"]
- **62% 的建筑专业人员**认为 AI 工具尚未完全可用于生产流程，但**概念/早期方案阶段**正是 AI 增益最大的窗口（同上）
- 前沿多模态模型（GPT-5.5 级）已能从一张空平面图直接产出**机器可检查的结构化布局规格**，无需针对该布局任务微调["https://developers.openai.com/cookbook/examples/multimodal/grounded_spatial_reasoning_layouts"]

### 1.2 AI 在创客空间规划中的价值

| 环节 | 传统做法 | AI 增益 |
|------|---------|---------|
| 需求梳理 | 手动访谈、Excel 清单 | LLM 自动解析需求→结构化空间清单 |
| 功能分区 | 经验+手绘泡泡图 | 自动生成多方案分区与邻接关系 |
| 布局生成 | 手工 CAD 反复改 | 秒级生成 3-5 个可选方案 |
| 面积测算 | 手动核算 | 自动校验面积/比例/动线 |
| 安全合规 | 对照规范逐条查 | AI 预检+规范提示 |
| 设备摆放 | 经验判断 | 邻接算法优化+碰撞检测 |
| 汇报迭代 | 反复改图 | 多方案对比、快速迭代 |

### 1.3 边界认知（重要）

- AI 擅长：**语义推理、方案发散、约束组合、结构化输出、快速迭代**
- AI 不擅长（2026 现状）：精确到毫米的几何、完整施工图、对"隐含意图"的把握——需要确定性工具与人工把关
- **正确姿势**：模型提议 + 确定性约束/几何校验 + 人工决策，三分工（详见第四章）

## 二、AI 空间规划的四种范式

> 依据学术综述：AI 在建筑空间布局规划中的技术演进可归纳为三大方法——**优化式 / 生成式 / 交互式**，各有优劣；再加上 2025-2026 兴起的**智能体式**，共四种。["https://pdfs.semanticscholar.org/58aa/5f72fd98c91a4ed561b3ea3167f2d1dccc51.pdf"]

| 范式 | 原理 | 优势 | 局限 | 代表工具/研究 |
|------|------|------|------|--------------|
| **优化式** | 把布局定义为约束+目标函数，用算法搜索最优解 | 可量化、可复核、性能最优 | 需人工定义目标和约束，创造性弱 | Snaptrude AI Adjacencies、TestFit |
| **生成式** | 生成模型（GAN/扩散/LLM）直接产出方案 | 创意强、发散多方案 | 需大量训练数据、几何精度不足 | 平面图生成AI、Maket.ai |
| **交互式** | 人机协同迭代，人在环路中 | 符合设计思维、可控性好 | 依赖交互质量 | 酷家乐AI布局、Rhino+DeepSeek工作流 |
| **智能体式** | 多智能体分工（需求解析/空间/评估/优化）协同 | 全链路自动化、可自我闭环 | 工程复杂度高、仍在早期 | 暗壳AI Agent2.0、Intelligent Co-Design、ArchAgent |

> 实践启示：创客空间规划最实用的是**交互式+智能体式混合**——用 LLM 智能体做需求分析与方案推理，用优化算法做邻接/面积校验，人工做最终决策。

## 四、核心方法论（两大权威来源）

### 4.1 两层规划法（Snaptrude 部门级空间规划）

> 核心思想：**大决策先于小决策、部门/功能块先于房间、比例先于精度。**["https://www.snaptrude.com/blog/ai-space-planning-at-department-level-design-the-bubble-diagram-that-actually-connects-to-bim"]

```
层级一：部门级（功能块）——定义主要功能区块及其面积、邻接关系（泡泡图）
层级二：空间级（细节）——在功能块内下钻到具体空间/设备/工位
层级间：双向同步——改大块，内部等比缩放；加内部空间，大块自动增大
```

**AI 邻接算法四目标同时优化**：
1. 邻接合规（相连空间尽量贴邻/共享墙）
2. 动线效率（最小化连接所有空间的走廊面积）
3. 比例尺寸（保持各空间所需面积且形状可建）
4. 边界约束（尊重功能分区与楼层分配）

> **对标本项目的直接应用**：L型434㎡可按"三专业功能块"做部门级泡泡图（新能源区/机器人区/AI区/智能制造区/公共教学区/储物区/管理区），用 AI 邻接优化确定各块邻接与动线，再逐块下钻到工位与设备级。

### 4.2 输入三分 + 规格输出 + 语义/确定性分工（OpenAI Cookbook）

> OpenAI 用 GPT-5.5 从空平面图生成办公室布局的完整方法论。["https://developers.openai.com/cookbook/examples/multimodal/grounded_spatial_reasoning_layouts"]

**三个输入严格分离（可复用、可替换）**：
| 输入 | 内容 | 创客空间对应 |
|------|------|-------------|
| ① 视觉证据 | 平面图/场地图片 | L型434㎡原始平面图 |
| ② 规划政策（SOP） | 功能空间清单+锚定设备+空间规则（硬/软约束） | 三专业功能区清单+设备清单+安全规范 |
| ③ 物体目录 | 设备/家具尺寸与放置规则 | 设备选型清单+工位尺寸 |

**两步推理**：先"语义接地"（从图/文本识别房间角色与功能）→ 再"生成布局"（基于语义方案+锚定需求放置设备）。

**输出=机器可检查的结构化规格（JSON）**，而非一张图：
- 可行性判断、假设清单、未满足约束
- 语义区域（zones）、家具放置（类型/坐标/尺寸/旋转/分区/依据/置信度）
- 动线路径

**评估三层分离**：
1. **有效性（确定性硬门）**：碰撞/越界/几何错误——一票否决
2. **语义接地分**：房间识别与功能是否忠于输入
3. **参考相似度**：与人工方案对比（软评分，不唯一标准）

**分工结论（最关键）**：**模型做高层语义解释（识别功能、分配程序、提方案），确定性代码做几何清理（边界/碰撞/旋转/重排）**——AI 推理不自证有效，必须被约束、检查、迭代。

## 五、AI 自主规划创客空间七步工作流

> 综合上述方法论 + 建筑 AI 工作流实践（DeepSeek+Rhino 十步思考法、AI 旧改三步法）设计的通用工作流。["https://www.iesdouyin.com/share/video/7650366151289418107"]

```
┌─────────────────────────────────────────────────────────┐
│ ①需求解析   输入场地/专业/人数/约束 → LLM 生成空间需求清单    │
│ ②约束定义   面积/安全/动线/楼层限制 → 硬约束+软约束清单       │
│ ③功能分区   部门级泡泡图（邻接关系）→ AI 多方案生成           │
│ ④空间下钻   各功能块内设备/工位布局（锚定+邻接优化）          │
│ ⑤校验评估   面积核算/动线/安全/碰撞 → 硬门+软评分            │
│ ⑥深化输出   结构化规格JSON + 平面图渲染 + 成本估算            │
│ ⑦沉淀回写   经验回写知识库，提示词/约束模板复用               │
└─────────────────────────────────────────────────────────┘
```

**每步的人机分工**：

| 步骤 | AI 负责 | 人负责 |
|------|---------|--------|
| 需求解析 | 把模糊需求转成结构化清单 | 提供真实需求、确认优先级 |
| 约束定义 | 补充规范类约束（安全距离等） | 提供硬性限制（结构/层高/消防） |
| 功能分区 | 生成3-5种分区方案 | 选方向、定邻接偏好 |
| 空间下钻 | 设备摆放建议+邻接打包 | 核对实际设备尺寸 |
| 校验评估 | 自动检查面积/动线/碰撞 | 现场复核（层高/水电/通风） |
| 深化输出 | 生成规格+渲染+估算 | 成本决策、供应商确认 |
| 沉淀回写 | 生成模板/复用资料 | 审核入库 |

### 6.2 与知识库既有成果的联动

> AI 规划不是替代知识库，而是**调用知识库**：把 [新能源汽车部件实训区设计](新能源汽车部件实训区设计.md)、[机器人实训区设计](机器人实训区设计.md)、[40人班制创客空间配置标准](40人班制创客空间配置标准.md) 等文档中的面积、设备、安全数据作为"物体目录+约束"喂给 AI，让 AI 在真实约束内生成方案，再人工校验。

**推荐组合工作流**：

## 八、局限与风险

| 风险 | 说明 | 应对 |
|------|------|------|
| **几何精度不足** | 生成式 AI 的平面图比例/尺寸不可靠 | 确定性校验+人工复核 |
| **语义误判** | 多方案可行时误判"意图" | 显式客户简报/需求，减少推断 |
| **幻觉规范** | AI 可能编造规范条款 | 对照知识库安全规范/官方标准核验 |
| **过度依赖** | 把 AI 输出当最终答案 | 硬门校验（碰撞/面积/合规）不可省 |
| **数据安全** | 上传真实平面图/设备清单 | 本地部署/脱敏处理 |
| **供应链验证** | AI 建议的设备/供应商需核实 | 结合供应商调研 |

> 学术与行业共识：AI 空间布局的**最大难点是语义接地**——不是"有没有可行解"，而是"多个可行解中哪个符合本项目的真实意图"。因此**明确的需求简报 + 严格的确定性校验 + 人工最终决策**是必备三件套。["https://developers.openai.com/cookbook/examples/multimodal/grounded_spatial_reasoning_layouts"]

## 八点五、实战验证与方法论优化

> 2026-08-28 用本方法论实际规划一个职业院校三专业共享创客空间（L型434㎡、硬装完成、楼上宿舍），完整的方法论验证结论、决策方法与可复用提示词模板见 [AI规划方法论-实战验证与提示词模板.md](AI规划方法论-实战验证与提示词模板.md)。以下是实战中验证的结论摘要与方法论优化。

### 验证有效的环节

| 环节 | 验证结论 |
|------|---------|
| 需求解析 | AI 主动算出"设备直接占地345㎡，仅剩89㎡给通道/储物"——**面积紧张这个核心问题是AI发现的**，不是人工预设的 |
| 两层规划法 | 先定功能块邻接关系再下钻设备，避免一开始陷入细节，非常有效 |
| 3方案对比 | 强制AI发散出"专业集群/噪音梯度/共享核心"三种逻辑不同的方案，避免单一偏见 |
| 硬约束清单 | 校验阶段逐条对照H1-H9，面积/安全/通道均通过 |
| 输入三分 | 场地/约束/设备目录分离，AI输出可控，未出现凭空编造 |

### 实战暴露的局限

1. **文字描述无法替代可视化**——AI能描述布局，但无法生成精确平面图；L型转角、柱子、门窗对布局的影响必须看图
2. **空间几何判断弱**——AI知道"每台12㎡"，但不知道12㎡在L型转角处如何摆放
3. **规范细节可能幻觉**——AI引用安全规范时需对照知识库原文核验
4. **现场信息缺失**——出入口数量、楼板承重、水电点位，AI无法从文档获取，必须现场踏勘

### 方法论优化建议（已纳入工作流）

| 优化项 | 原方法 | 优化后 |
|--------|--------|--------|
| 步骤③后增加**平面图可视化校验** | AI出泡泡图文字描述 | 用酷家乐AI布局/Snaptrude把泡泡图变成实际平面图，验证空间可行性 |
| 步骤④明确**AI概念→CAD精确**分工 | 要求AI出设备布局 | AI出概念布局（位置/邻接/面积），精确几何交给CAD工具 |
| 步骤①强制输出**面积总账** | 分类列设备 | 必须先算设备直接占地合计，再判断面积是否紧张 |
| 步骤②增加**现场踏勘确认项** | 仅列约束 | 增加"出入口/承重/水电/排烟点位"等AI无法获取的待确认清单 |
| 步骤⑤增加**平面图叠合校验** | 文字校验 | 将AI布局与真实平面图叠合，检查柱子/门窗/承重墙冲突 |

### 本次规划的关键创新（可复用）

- **竞赛场地可收纳复用**：60㎡竞赛场地与公共教学区分时复用，解决面积紧张——这是AI在3方案对比中提出的，人工确认可行
- **高噪音区集中治理**：B制造+C机器人集中在横向臂一侧，铝型材+亚克力围合，适配楼上宿舍约束
- **中央共享核心**：呼应平面图原文"相通部分可共用"，三专业围绕共享核心布局

## 十、平面图理解实战：从 PDF 矢量到语义识别

> 2026-08-28 项目实战：AI 规划的前置瓶颈不是"生成方案"，而是"理解平面图"。本章记录从 CAD 导出的 PDF 平面图中提取墙/门/窗/柱的完整方法论、工具链、踩坑经验。这是 AI 自主规划的**第零步**——不理解场地，所有规划都是空中楼阁。详细方法论与规则见 [../06-资源索引/AI平面图理解与矢量提取方法论.md](../06-资源索引/AI平面图理解与矢量提取方法论.md)。

### 10.1 为什么需要专门的平面图理解

AI 规划方法论（第四章）的"输入三分"中，①视觉证据（平面图）是最关键也最难处理的输入。实战暴露的问题：

| 问题 | 表现 | 根因 |
|------|------|------|
| Seedream 等图像生成模型无法精确绘制平面图 | 比例失真、门窗遗漏、L型转角错误 | 生成式模型不擅长精确几何 |
| 多模态 LLM 直接"看"平面图 | 能描述大致布局，但无法输出精确坐标 | 视觉理解≠几何提取 |
| 纯文字描述布局 | 无法体现柱子、门窗、承重墙对布局的约束 | 空间几何判断弱 |

**结论**：需要一条**确定性的矢量提取管线**，把 PDF 平面图转成机器可操作的结构化数据（墙线段、门洞坐标、柱位、窗位），再喂给 AI 做规划推理。

### 10.2 工具链与五步工作流

```
PDF平面图 → ①矢量提取 → ②规划区裁剪 → ③语义识别 → ④规则过滤 → ⑤视觉自检+人工迭代
```

**① 矢量提取（pymupdf / PyMuPDF）**

```python
import pymupdf
doc = pymupdf.open("平面图.pdf")
page = doc[0]
drawings = page.get_drawings()  # 提取所有矢量绘图对象
# 每个drawing含: items(线/曲线/矩形), color, fill, width, rect
```

关键：CAD 导出的 PDF 通常保留矢量路径（线、贝塞尔曲线、填充矩形），不是位图。`get_drawings()` 可精确提取每条线的坐标和颜色。

**② 规划区裁剪**

- 用户确认规划区边界（L型多边形顶点）
- 用 `point_in_polygon()` 过滤掉规划区外的元素（公共设施、宿舍等）
- 用 SVG `clipPath` 实现可视化裁剪

**③ 语义识别（规则-based，非 AI）**

| 元素 | 识别规则 | 踩坑点 |
|------|---------|--------|
| **柱子** | 黑色填充矩形，宽高比接近1:1（ratio<2.5），尺寸<50pt | **长条形黑色填充（ratio>4）是墙体截面，不是柱子** |
| **门** | 弧线（开门轨迹）+ 短线（门板），弧线在墙外侧 | **弧线位置≠门洞位置**，门洞在墙上，弧线是开门方向 |
| **窗** | 外墙上的小填充矩形，通常成对出现 | **东墙上的柱子会被误识别为窗**，需排除与柱重叠的 |
| **墙体** | 黑色/灰色线段，或长条形填充矩形 | 外墙粗线，内墙细线 |
| **设备基座** | 规划区内的橙色/特殊填充矩形 | 需人工确认 |

**④ 规则过滤**

- 柱子：`ratio < 2.5 and width < 50 and height < 50`
- 窗：排除与柱子距离<20pt的误识别
- 门：去重（双开门两个门扇距离<40pt合并），只保留用户确认的
- 所有元素：`point_in_polygon()` 过滤规划区外

**⑤ 视觉自检 + 人工迭代**

```python
# SVG转PNG用于视觉检查
qlmanage -t -s 1200 -o /tmp output.svg
# 然后Read PNG图片检查
```

**关键教训：必须做视觉自检！** 本次门的位置迭代了9个版本，根因是前8版都没有做视觉自检——代码逻辑正确不代表视觉结果正确（弧线位置被当成门洞就是典型）。

### 10.4 方法论沉淀（可复用）

1. **矢量优先于位图**：只要有 CAD 导出的 PDF，就用矢量提取，不要用图像识别
2. **规则识别优先于 AI 识别**：墙/门/窗/柱有明确的几何特征，规则比 AI 更可靠
3. **视觉自检不可省**：每次生成标注图后必须转成图片肉眼检查，代码逻辑≠视觉正确
4. **人工确认是硬门**：门的位置、柱子的数量，必须由懂建筑的人确认，AI/规则只能提案
5. **坐标系统一**：全程使用 PDF 原始坐标，避免多次换算引入误差
6. **规划区先裁剪**：先确认规划区边界，再做元素识别，避免被外部元素干扰

### 10.5 局限性

- 本方法适用于 **CAD 导出的矢量 PDF**；扫描件/照片需先用矢量化工具（如 Adobe Illustrator 图像描摹、在线 SVG 转换）
- 复杂的建筑符号（标高、索引、详图标记）未做识别，需人工过滤
- 多层平面图需逐层处理，本方法针对单层
- 门的开门方向（弧线）识别依赖 PDF 中是否保留弧线，部分 PDF 可能只有门板线
